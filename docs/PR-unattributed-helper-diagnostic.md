# fix(ci): retain narrowly scoped unattributed helper originals

The failed-command finalizer passes its actual retained-image records to the existing report collector. A fresh or hash-changed report in the observed SwiftPM helper filename family may retain its exact bytes under unattributed-helper-diagnostics only when its cohort record matches actual owned PID/start/arguments and its retained image is a confined regular file. The optional leading dot matches the observed report family. Names and timestamps limit discovery only; they never prove report identity. An unknown baseline hash cannot establish a changed candidate. Unrelated names, unchanged baselines, missing/unowned/refused image records and inaccessible image files remain metadata-only.

The strict report parser and exact PID/start/path attribution function are unchanged. Fully attributed reports retain their existing matched-crashes path. Candidate records keep matchedActualProcess=false, attribution unproved, null/partial parser identity as actually returned, and a separate observedContext that is explicitly not a report-process join. Malformed originals can be preserved without repairing their parser or inventing identity. All existing fixed-root, no-symlink, regular-file, current-size/bounded-read, stable-hash retry, whole-original/no-truncation and shared512MiB budget guards remain. Failure capture does not change the original make status, command budget or process monitoring.

The collector caches each source-path/digest after verified retention so repeated drain polls neither copy nor charge the same bytes again. A later exact process-history join may promote the same retained original to matched-crashes by moving it, recording promotedFrom and preserving its hash/budget. Changed or disappeared source reports retain earlier original references in retainedVersions, even when a later version is refused by the cap. No all-machine report upload, new discovery root, watcher/framework, timeout, stack or concurrency change occurs. The wrapper's manifest/upload already includes retained evidence files; workflow and Makefile stay unchanged.
