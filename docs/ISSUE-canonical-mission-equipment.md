# Canonical mission equipment

Mission equipment and finite missiles must use the existing physical inventory rather than a second owner or a counter that can recreate spent rounds. Original UUIDs, acquisition provenance, loan obligations, legacy condition and modifications must survive fitting, storage, transfer, consumption and save migration.

The implementation composes the accepted mission engine with the central actor-owned runtime. Shared immutable contracts precede pure issue and ammunition providers, then the Commander migration and native/Script adapters. All mutations require complete candidate validation before one publication. Virtual XYZZY ammunition has an explicit source and changes no finite round or loan record.

Compatibility requires ordinary save behavior and Script format 21 to remain intact. The shared schema checkpoint alone does not admit version-2 Commander saves; that change must arrive with all consumers and migration. Full composition, focused regressions and the maintained quality gate remain required before release.
