# Accelerate startup filled ship panels

The title and credits native view can render consecutive eligible filled triangles through a Metal offscreen render pipeline. Original projection, face selection, clipping, shading, rotation, materials and painter sorting remain in EliteCore. The renderer uploads those triangles in order, renders their fill and existing 0.25 logical-unit round overlap stroke with eight-sample coverage, and composites an immutable transparent image at the original drawing-stream position. Non-panel commands and unsupported polygons split runs; bounding-quad fragments outside a triangle/stroke are discarded rather than erasing earlier panels.

The existing colour interpretation is retained, including opaque panel alpha. The image uses the same CGColor colour space and premultiplied bytes. Device-pixel-aligned bounds account for translation, axis-aligned scale and flipped Y; the original CGContext canvas and flight clip still apply. Quartz and Metal antialiasing are not promised byte-identical: the approved tolerance permits differences only within one backing pixel of actual shape/stroke boundaries. Interior colours, painter order, opacity, orientation, clipping and geometry have no tolerance waiver.

Preparation compiles asynchronously, following the existing planet renderer's ownership pattern without changing its private terrain pipeline. Metal queues, buffers and textures remain on the main actor. Each frame permits at most four acceleration attempts and a total of 1536 squared output pixels. Each run accepts at most 120,000 original triangles; copied vertex storage, MSAA/resolve textures, aligned output buffer and immutable image bytes are bounded. Only current Metal resource storage is reused, with no animation-image, mesh or geometry cache.

No destination drawing occurs until a complete successful image exists. Preparation, missing device or unsupported eight-sample rendering uses Quartz. Unsupported transforms, unsafe coordinates, collapsed triangles, bounds and exhausted budgets refuse acceleration. Runs whose padded stroke/antialias bounds meet a CGContext clip boundary also use Quartz: grouping their fractional per-panel clip coverage into one composite could change opacity. Allocation, encoder and command failure also returns to Quartz and disables a failed renderer to avoid repeated stalls. Export entry points and other game screens retain the default Quartz path. The existing startup observer records actual per-draw CPU, Metal or mixed panel execution; ordinary planet reporting remains unchanged.

Four focused methods cover packing/order/colour and allocation refusal; actual GPU painter/clip/interior parity with translated 1x and flipped Retina 2x contexts; unavailable/preparing/failed preparation and exact wireframe fallback; and original SH123 geometry, two rotations, retained image ownership and an actual flipped GameView draw. GPU tests require hardware execution and cannot qualify by silently falling back. Source checks, independent review and focused execution are pending. A later authorized matching native title observation must establish actual end-to-end benefit; no smoothness, numerical speedup, full CI, sanitizer, leak or release acceptance is claimed here.
