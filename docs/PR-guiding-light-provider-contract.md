## Implementation

The manifest is immutable native provenance created before acceptance. The non-Codable source/facts seam accepts only internal native producer input, stamps the actual commander/player/runtime epoch/revision/physical time, and checks current ordinary physical actors for live statuses. It does not create or authenticate G1's absent registry itself.

`ProviderMissionObservation` folds at most 0.1 seconds of admitted native movement. An explicit manifest-request window requires continuous actual contact, communication, free flight, range and relative-speed limits. Route calibration uses actual forward displacement and physical time; desired orbit phase has no input. Reload runtime epochs, scene rebinds, gaps, pause, defence, negative movement and absent intervals cannot bridge progress. Repeated/backward intervals are refused. Progress is a capped value, three checkpoint bits and one transient baseline; normal saves capture it without per-frame events, commands, histories or writes.

`ScriptProviderContractState` retains one instance/item, frozen terms, exclusive branch, bounded native evidence, one pending review and nine finite receipt kinds. Urgent confirmation binds a fresh explicit token to the runtime epoch. The original core is joined to an actual collected or settled computer-core lot; it remains the player's property. Care joins an actual `.care` receipt for the original EMP person, owner, operation and exact Crimbo dock. Sale is distinct from care; loss and escape never authorize rescue. Native causal order, rather than UUID sorting or unrelated ledger counters, selects the earliest betrayal.

Payments use existing decicredits: full 30000 OR urgent 15000 OR recovery 20000, plus optional crew 5000 once. Payout and terminal relay consumption are staged together. All unpaid crew rewards are voided by betrayal; an actually paid historical reward remains recorded. At maximum cash, an innocent pending claim keeps actual lost custody and active closure pending; settlement may retry without new history. Unknown relay observations preserve established custody. The last native relay order prevents replaying an old world/aboard transfer.

Native actions and observations stage private candidates. The actor action seam uses existing `scriptCommand` and full native/script publication. Finite native transitions drive presentation-only Lua; it cannot issue cash, payload, actor or finish commands. Terminal completion uses existing completion validation, receipt construction and dependent receipt propagation. Back/rearm/review overwrite bounded state and do not create lifetime receipts or a per-frame journal.

Station-board and Gallery controls stage one transient intent. The presentation contains labels, stable public IDs and availability only, with no facts, seals, commander or authority. A staged intent binds the exact painted page and presentation epoch. The native actor bridge must check them first, resolve fresh facts during that same turn, and then call `performProviderMissionIntent`; cached presentation or decoded flags cannot authorize a commit.
