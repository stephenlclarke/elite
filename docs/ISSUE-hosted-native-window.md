# Native viewport fixtures on constrained displays

PR #19 [hosted run 38939510614](https://github.com/stephenlclarke/elite/actions/runs/38939510614) compiled with Apple Swift 6.1.2 and Xcode 16.4, then ran 897 tests. It failed with 13 issues across ten native equipment and work-control methods. Every issue was a strict requested-height assertion in the two window fixtures; the matching width assertion passed. Larger requested windows were affected, so the outer minimum-window size alone cannot explain the failures. The original raw log is retained with SHA-256 `c1203bbfca5c3285fb9898b132dffc78ef75ace2e2001f4c26c4ce64400e5a20`.

AppKit constrains real window frames to their screen. A local actual-window probe demonstrates that its default constraint reduces a requested 768-by-1271 frame to 768-by-1039 on a display with a 1039-point visible height. The native test window retains the requested 768-by-1239 content viewport. The hosted run did not record its screen geometry; its exact screen height remains unknown.

The two fixtures need exact logical viewport sizes to test rendering, real window coordinates and ordered native input independently of display size. The correction injects a test-only NSWindow subclass that preserves its requested frame. Production retains its existing default NSWindow construction and screen-fitting policy. Bounds and interaction assertions remain strict; failures now include requested size, actual frame/content/bounds, screen and visible frames, and the default AppKit constraint. See the [implementation and validation](PR-hosted-native-window.md).
