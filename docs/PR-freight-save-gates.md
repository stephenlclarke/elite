# Store native supplied freight in schemas 29 and 30

Native supplied freight now selects schema 29, or 30 when Alien companion storage is present. The reader joins validated freight missions, contracts and world state, checks the exact feature/envelope match, and rejects freight custody in legacy raw files, scrubbed headers and older envelopes. Schema 28 stays unsupported; provider-only writes fail before publication, while valid provider claims can coexist with freight in 29/30. Explicit null provider custody is rejected before optional decoding can erase it.

The change preserves the old 2-27 reader range and writer selection, chunk names and hashes, generation UUIDs, typed values, file limits, symlink protections, atomic publication and Alien page codec. The Alien header validator receives its existing policy version according to actual companion presence, so schema 29 does not accidentally require Alien pages. Game-over freight requires retained pending loss or terminal evidence. Typed `Game.load` refuses native freight/provider state that needs its versioned world; ordinary typed Commander loading remains available.

Six new test methods cover genuine native freight across the 29/30 and provider-presence matrix, old/raw/header null and shape rejection including UUID object/pair forms, downgrade and typed-load refusal, false feature envelopes and unsupported provider-only writes, rehashed corrupt chunks with runtime/disk rollback, and actual fatal pending-loss persistence and resolution. Provider and empty Alien additions are explicitly storage-only compositions using the actual freight owner's fresh identities. They make no provider readiness, crew care or Alien acquisition claim. Existing freight partial/final transaction tests and all original ship definitions are untouched.
