# Add native authored NPC wormhole transit

Authored NPCs currently have local steering and retained source-system bodies. Ordinary `initiateNPCJump` spends ordinary fuel and retires a ship; it supplies no physical wormhole, surviving destination actor or mission receipt. Reusing that removal as transit would invent arrival and could falsely satisfy escort or destruction objectives. The Mission Researcher contract instead requires an actual working drive, source-resolved native distance/fuel, a real spatial opening and physical entry, retained finite resources and logical identity, and actual destination admission before an arrived event.

Implement this through GameRuntime's existing serial simulation, native actor factory, collision proof, calendar and durable publication boundaries. No actor per NPC, unseen GPS ship, direct arrival flag, destination teleport, cloned crew/resources, destruction/removal credit or campaign reward may replace those authorities. Replays, unavailable scenes, expiry and disk refusal must retain the same leg and ship without another debit. NPC journey time must not multiply the commander transit clock.

The independent original-world production leaf is a real integration dependency. G1 owns the single authenticated catalogue, direct Cartesian light-year StarSystems, native endpoint validation and navigation/market/travel integration. This transit leaf authors its resolver against that provided interface, with exact cached records and their approved catalogue fingerprint. It must compose with G1's leaf before compilation or runtime qualification; it does not install another catalogue, invent records, authorize PLUGH through an ordinary-world alias or establish playable mission acceptance. Existing Game/ScriptCalendar overlap is explicitly handed to G1 for manual composition. See the [PR notes](PR-native-npc-wormhole-transit.md).
