# PR #7: playable shipyard, consistent controls and TOML ship catalogue

The showroom now exchanges real player hulls and compares the native values that govern their flight. All 167 definitions load from individual resource-backed TOMLs containing specifications and geometry; 158 are flyable adaptations and nine are display objects. Every record has a renderer-generated rotating GIF and an entry in the generated central catalogue.

## Behaviour

- Numbers select main areas; arrows, Return, Escape and K provide the common navigation. Docked 6 opens the showroom. Secondary showroom actions are visible buttons; search, pane focus, nested Back and number routing are consistent. Escape never ejects the escape pod. MacBook flight uses arrows, Space, Delete and Return; Tab selects targets. Specialist actions remain in the Flight menu.
- Status/inventory, chart facts, routes, system data, showroom details and XYZZY use viewport bounds. Scrolling hints appear only for overflow and indicate available direction; help uses the underlying screen and treats exchange quotes as a separate context. In-flight prices advertise Back, not station purchasing.
- Native comparisons carry the same equipment/policies on both hulls and mark BETTER/WORSE/SAME in colour and words. Physical hold capacity remains visible alongside unlimited cargo. Source profiles stay inspectable separately. A-Z and standard combat-power sorting preserve filter, selection and list position.
- Trade review shows price, 75% hull allowance, net cost/credit, resulting balance and fit constraints. Back is initially selected. Confirm revalidates the quote atomically. Cargo, fuel, missiles, paid equipment and mission property transfer intact; incompatible or unaffordable exchanges explain the block. Subsequent exchanges work from any owned hull. Speed/acceleration/handling, energy/shields/recharge, cargo, tanks/jumps and weapon fitting use the purchased definition.
- Ownership migrates older Cobra saves. Save As/Open support alternate files. Startup restores the last successful save through GameRuntime without rewriting it; missing/corrupt saves offer recovery or a new Jameson. The save format restores docked commander/mission state, not a mid-flight scene. XYZZY L or its clickable row resets legal status to Clean and persists the relevant wanted amnesty without changing mission progress.

## Data and media

`Sources/EliteCore/Resources/Ships/*.toml` is the only maintained runtime catalogue/model source. SwiftPM copies the folder unchanged into the packaged app and uses pinned MIT TOMLDecoder 0.4.5. The removed monolithic JSON resources cannot drift. Original source profiles, model custody and 63 original notice files are preserved. Original encounter ship blueprints/combat values also load from the same TOMLs; binary geometry digests and existing mission regressions keep their behaviour intact. Seventy-four imported models retain their original terms; 93 original gap designs are MIT and their provenance stays in Markdown/TOML rather than app badges. The approved Cobra icon is unchanged.

`make ships` hashes each complete TOML, its embedded design and shared rendering/simulation/settings dependencies, regenerates changed GIFs, then generates `docs/SHIP-CATALOGUE.md` and `docs/SHIP-PROVENANCE.md`. The manifest also detects missing/corrupt outputs. `make ships-check` rejects stale media/reference content and runs in CI. A real model refinement rebuilt only 27 GIFs and reused 140; the subsequent three-file refinement rebuilt three and reused 164. Every GIF has 24 frames and visible animation at 256-square resolution. README media uses `make readme-media`.

## Validation and compatibility

The current suite contains 208 Swift regressions and nine Python assembly/data/dependency checks. It covers exchanges, conflicts, subsequent trade-ins, real flight values, legacy ownership, schema rejection, save selection/recovery, legal reset, contextual help, sorting, viewport boundaries and all 167 models throughout rotation. The final local `make ci` passes all 208 Swift regressions and nine Python checks, with 92.70% line coverage, clean Thread Sanitizer (73.5s), clean Address Sanitizer (351.3s) and zero detected leaks. `make ci` enforces coverage >=80%, Thread/Address Sanitizers and macOS leaks. Final exact-head results are recorded in [the required PR checks](https://github.com/stephenlclarke/elite/pull/7/checks); authoritative Sonar runs only after protected merge to committed main with that exact SHA.

Native review exercised compact 512x518, standard 768x768 and wide full-screen layouts; status boundaries, station trade/equipment, help/pause, chart search/routes, gallery/rumours, showroom search/pin/sort, a real Cobra-to-Boa purchase, launch/flight/automatic dock/save/load and return exchange, Save As/relaunch, corrupt-save recovery and XYZZY Clean. Evidence is saved locally in `reports/ui/shipyard-audit`. The whole AppKit entrypoint remains a coverage exception because CLI exports, OS dialogs and startup error paths need native evidence; these were exercised through the packaged app rather than padded tests. Physical trackpad gestures, long campaign playthroughs and live Game Over remain limits of this pass; deterministic core/native-renderer regressions cover their corresponding code paths.

Ships use the existing solo automation and normalised point-based docking envelope. Historical crew counts remain source facts; no hired-crew, passenger-cabin, surplus-equipment-storage or full-scale capital docking simulation is claimed. Project prices/conversions are documented, and unsupported transfers are blocked. Research-ready mission handoffs remain queued separately in [the implementation ledger](MISSION-IMPLEMENTATION.md).
