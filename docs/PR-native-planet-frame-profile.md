# feat(diagnostics): observe native planet frame pacing

The optional `--profile-planet-frames /absolute/new/output/directory SOURCE_SHA compact|fullscreen` mode runs one independently launched window case. It creates a normal commander at a deterministic high-technology corporate industrial world. Fullscreen waits for actual AppKit acknowledgement while still docked. Both modes warm the ordinary window/renderer, launch through key 0, coast for one physical second, then feed held three-finger acceleration through the real trackpad/control path on the original +Z heading. Actual camera keys 0/1/2/3 keep the approaching or receding body visible. Each mode starts a separate fresh game; no live pose, resources, seed or invulnerability is changed. See [the measurement gap](ISSUE-native-planet-frame-profile.md).

The existing AppDelegate deadline/sleep, ordered commands, GameRuntime advance, GameView and renderer remain the measured path; there is no manually paced draw loop. A main-actor observer records submitted frame IDs, first draws of distinct submissions, repeated draw events and coalesced/undrawn submissions explicitly. Phase-specific first-draw intervals are never replaced by duplicate redraws or cleared before an outstanding submission draws. Raw monotonic spans cover commands, actor advance, submission, presentation and drawing, including actor queue or GPU waits. They are not CPU-only time, physical scanout or input latency; missed sixty-Hz intervals are rounded estimates.

The report retains actual initial hardware/assists, anchors/radii, ongoing pose, physical/game clocks, camera-relative ranges, controls, viewport pixels and backend. Completion requires safe close planet and star ranges, both front-to-rear crossings, actual travel beyond the sun's far plane, normal unsteered inputs and distinct high-resolution planet draws. The original forward line is geometrically expected to pass the planet at about 1.795 radii and sun at 4.746 radii; the execution must prove the actual trajectory. A renderer-generated rear-view PNG is captured after the excluded settling phase. Source and executable identities, raw draw events and percentile summaries are saved. Success means a complete controlled measurement, not a smoothness or release gate.

Results remain candidate-only unless a separately identified baseline uses the identical instrumentation, fresh scene and input protocol and its actual trajectory is verified. The diagnostic session has no UserDefaults, uses only its new temporary output path, disables startup restoration/default external script loading and never chooses a commander destination. Normal launches retain a nil observer and their existing runtime/session defaults. Strict formatting and whitespace checks pass; compilation, isolated native execution, protected-input verification, actual baseline comparison and final CI remain pending. Source alone proves no performance result.
