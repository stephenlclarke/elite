# Keep freight confirmation snapshots in an attempt-local owner

Current-state preparation and cold validation finish before the candidate Game is copied, at the original transaction point. A private synchronous non-Sendable owner holds the candidate, mutable mission and owned cargo; a separate selection owner retains the original selected values. Neither owner is stored in Game, serialized, sent across actors, cached as authority or retained after the call. The implementation follows the existing mission acceptance and event attempt ownership pattern.

The original confirmation body is divided into preparation, mutation, completion, full validation and publication phases. All original guards and operations retain their order and original-versus-candidate receiver. Delivery's full committed mission temporary returns before full Commander validation starts. Final publication still happens only after every original operation and check succeeds, so thrown errors discard the private candidate and retain the original value state. Game and ScriptInstance COW representation, schemas and the existing key publication barrier are unchanged.

The freight contact, quote and owned-cargo/Commander validation arguments borrow their original read-only mission, engine and Commander values. Their predicate bodies are unchanged. Freight generation, offer validity, structural plan validation, all shared mission predicates, full binding equality, ownership/provenance/custody, inclusive deadlines, payment and rollback checks remain intact; no validation shortcut is introduced.

Static validation reassembles the entire original confirmation body in token order after reversing only owner references and phase boundaries. It also compares the complete contact, quote, closed owned-unit request and cargo/Commander validator bodies, reverses both whole changed files, and verifies every other source and existing test file byte-for-byte against the parent. Strict Swift formatting, Markdown lint and whitespace checks are the author checks. No compiler, test, native app, renderer, profiler, disassembly or ABI job is run by the author. These source properties do not establish emitted allocation size, stack margin or runtime acceptance.

Independent review is required before the coherent batch build. Runtime qualification starts with the unchanged `freightRealTravelExpiryKeepsEarlierDeliveryAndOrdinaryGoods` reproducer using coverage-enabled/default-stack/default-concurrency settings. Existing freight generation, delivery, custody, persistence and version-gate tests cover cold structural/authenticity validation, declared partial/all choices, inclusive deadline/expiry, owned versus ordinary cargo, failed-save rollback and restoration. Test assertions, fixtures and budgets are unchanged. Full `make ci`, standard completed clean PR review and required final-head checks remain separate merge and release requirements.
