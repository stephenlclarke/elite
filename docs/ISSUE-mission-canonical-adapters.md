# Canonical Mission consumer integration

Accepted Mission commands previously mutated a separate physical equipment bag.
The integration uses the canonical inventory and sealed provider transactions,
retaining original issue identities, rights and historical condition metadata.
The old bag is a migration DTO only; no old mutation or minting getters are used.

## Source milestones

The early DTO and reciprocal validation seams are pinned in `1c5574e`, `9fce7a4`
and `bb82277`. The last fixes present personal substitutes for legacy issued
originals. Original failed source evidence remains in history.

`ed32cfd` adds sealed-consumption event access, exact staged application, retained
fitting receipts and pure consumption regressions. Actual shared finite-round
consumption stages only its original loan record. Virtual consumption changes
neither physical inventory nor the loan ledger. Missing mission rights throw.

Mission commands use the actual trusted event and validated receipt ID to derive
their command identity. Admission, fitting and settlement quote and apply through
G2's sealed provider. Settlement budget uses its read-only physical projection;
personal restoration policy is not duplicated. Refits retain new displacement
history. Complete issue state is staged before each command in one handler.

Budgets use actual projected native hold, current freight, protected cargo and
cabins. The shared per-item predicate exempts only genuine intrinsic Basic
foundations; ordinary node costs remain nonzero. Player resources preserve their
fractions when native capacities change, with exact values retained otherwise.

Save publication uses existing calendar-ledger state to preserve loaded empty
format-21 containers. Canonical inventory alone does not promote an ordinary
commander. Gallery context changes follow private write and publication, or
parent restoration. Trial hardware starts from an explicitly configured fresh
