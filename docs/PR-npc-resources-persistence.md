# Integrate actual NPC telemetry, finite cargo and persistence

The gameplay branch reads each physical NPC's resource state rather than inventing values from hostility. New native craft use their actual catalogue performance and fitted scoops; original mission craft retain energy-only behaviour and unknown fuel. The tier-gated target panel displays recorded provenance and native commodity units with compact paging. Ordinary NPC state persists through save/load, docking and camera culling, then re-enters through the shared allocator under a fresh physical identity without replenishing resources. Offscreen craft coast and cool/recharge during actual simulation time.

Ordinary ship deaths register finite manifest fragments before removal. A full ledger retains the corpse and its incident for retry, including outside the local camera bubble. Physical scoop collection frees custody exactly once. Docking and saving first settle pending deaths; refused settlement cannot silently erase them. Save writes operate on a candidate, atomically replace the file, then publish the runtime state. Disk-only physical bindings are cleared without altering the live bindings. Escape uses a candidate too, preserving its pod and cargo if docking cannot complete.

This integration also contains the coordinated renderer and station/control changes already documented in their own handoffs, together with tested pure progression, purchase and salvage foundations. Those foundations are not complete playable shops, salvage controls or special weapon fittings. The scriptable mission engine remains a separate owner's branch. Typed missile runtime work and the loaded-component API checkpoint are also isolated and are not part of this acceptance source.
