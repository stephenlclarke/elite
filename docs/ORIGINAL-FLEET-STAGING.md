# Original fleet definition and texture staging

The original fleet preparation tools preserve 171 authored specification records without replacing the active ship catalogue. The generated immutable Swift definitions in `OriginalFleetDefinitionData.staged` retain complete nested authored values, provenance and explicit native representations. Four records (`SH040`, `SH043`, `SH081`, `SH123`) retain their original native range conflicts instead of being clamped. All definitions remain `runtimeReady == false`; approved mesh availability, original market policies and other integration blockers remain separate requirements. This is staged input for a later single-catalogue integration, not an additional live resolver or a claim that every hull is playable.

The [reference table](research/original-fleet-reference/fleet-reference.md) and [CSV](research/original-fleet-reference/fleet-reference.csv) preserve raw authored units. Their [manifest](research/original-fleet-reference/manifest.json) records generated reference fingerprints. The [hull texture inventory](research/original-fleet-reference/hull-texture-bindings.json) distinguishes declared texture entries from indices actually used by faces and records source discrepancies without rewriting them. `original-fleet-definitions.manifest.json` records typed definition provenance and representation checks outside runtime resources.

Original texture assets are bundled independently under `Sources/EliteCore/Resources/OriginalShipTextures` through the explicit SwiftPM copy rule. Three finite `l337-` asset identifiers use authenticated PNG/RGBA bytes at one-time initialization; source, albedo, height, normal and roughness payloads retain their original fingerprints, while the renderer currently consumes the colour pixels. Original design `textures` and `faceTextures` preserve authored finite repeating UVs and explicit untextured `-1` faces. Invalid references, unsupported wrapping, malformed UVs and mixed original/imported mappings are refused. Imported texture lookups keep their existing implementation. No current ship definition is replaced merely by adding this loader.

Preparation tools are `Tools/prepare-original-ship-textures.py`, `Tools/export-original-fleet-reference.py` and `Tools/generate-original-fleet-definitions.py`; use their documented CLI options with the approved source/staging input and a new output destination. Generated bytes are never hand-edited. The frozen MBA evidence retained five texture-tool tests, four reference-tool tests, four definition-generator tests, one complete reference export and one complete definition generation. Those jobs are not repeated merely for integration. Central Swift resource, UV, current-definition and affected renderer tests remain pending the combined candidate build. A renderer proof and activation work are still required before claiming a visible new playable fleet.

Original market preparation is also staged under `Sources/EliteCore/Resources/OriginalMarkets`, with an explicit package copy rule. `Tools/prepare-original-markets.py` preserves the accepted 2,048-world joins and 34,816 initial authored quotes, authenticated against their source manifest. The immutable reader authenticates the initial seeds; OriginalLiveMarkets now owns changed live stock in Commander and seeds pristine worlds from those exact quotes. The active Universe uses the same OriginalWorldCatalogue records and Cartesian light-year coordinates. See the [live world implementation and limits](ORIGINAL-WORLD-RUNTIME.md); fleet, player ship, equipment and later economic-epoch policies remain separate.

Original route preparation now shares one bounded synchronous search kernel with the existing navigation computer. The staged original-world adapter uses the catalogue's existing identities and Cartesian light-year distances, with explicit visible-world, fuel and later-refuelling assumptions. The live navigation computer now consumes the installed original-world systems through that same kernel. Focused source and runtime acceptance is recorded separately; route preparation does not guarantee later refuelling or station admission.
