# fix(ci): enable child runtime crash backtraces

The existing capture-quality.py launcher copies the parent environment through a tiny pure helper, replaces SWIFT_BACKTRACE with enable=yes,interactive=no,color=no,output-to=stderr,threads=crashed,registers=crashed,images=mentioned, and passes that copy only to its existing owned make ci child. Compiler and test descendants inherit it within that process tree. The parent environment and unrelated coverage/sanitizer settings remain unchanged. The run record adds only the effective fixed setting as runtimeBacktrace; no environment dump is added. Existing stderr forwarding retains runtime warnings and backtrace bytes in ci.log.

Original argv, default suite, session creation, exit/status propagation, monitoring, raw byte forwarding, report collection, strict parser/attribution and artifact limits remain unchanged. There is no workflow, Makefile, signing, debugger, stack-size, concurrency or timeout-setting change. The runtime's own default frame limit and backtracer timeout remain. Its documented signal-handler implementation may allocate its own alternate signal stack; no application or CI stack setting is changed.

## Primary support and limits

The exact upstream [Swift 6.1.2 backtracing documentation](https://github.com/swiftlang/swift/blob/swift-6.1.2-RELEASE/docs/Backtracing.rst) defines the selected settings. Its [macOS signal handler](https://github.com/swiftlang/swift/blob/swift-6.1.2-RELEASE/stdlib/public/runtime/CrashHandlerMacOS.cpp) includes SIGBUS, captures the actual crashing thread/fault context, leaves existing handlers alone, restores default signal handling and returns to crash after invoking the backtracer. The [runtime initializer](https://github.com/swiftlang/swift/blob/swift-6.1.2-RELEASE/stdlib/public/runtime/Backtrace.cpp) defaults macOS capture to TTY and explicitly disables unsupported privileged executables or missing auxiliary backtracer, with warnings when explicitly enabled.

The exact [SwiftPM environment construction](https://github.com/swiftlang/swift-package-manager/blob/swift-6.1.2-RELEASE/Sources/Commands/Utilities/TestingSupport.swift) starts with Environment.current and preserves SWIFT_BACKTRACE. Its [test command](https://github.com/swiftlang/swift-package-manager/blob/swift-6.1.2-RELEASE/Sources/Commands/SwiftTestCommand.swift) forwards the actual helper's stdout/stderr and reports signal termination. [UserToolchain](https://github.com/swiftlang/swift-package-manager/blob/swift-6.1.2-RELEASE/Sources/PackageModel/UserToolchain.swift) resolves the installed helper without changing its signature.

These upstream sources establish supported behavior, not successful capture by the actual Xcode vendor runtime/helper. The actual Apple helper executable/signature was not retained; the test image's signature cannot establish helper eligibility. Platform/hardened executable flags, missing get-task-allow, unavailable swift-backtrace or an existing SIGBUS handler can prevent capture. Missing output still leaves the fault site unknown. Raw runtime text does not grant OS-report attribution: actual owned-process history and image/dSYM UUID evidence remain separate. No signing change or speculative debugger attachment is included.
