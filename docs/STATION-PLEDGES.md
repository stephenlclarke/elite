# Native station pledges

This source addition is being authored against `ea87bc57083926349a45f5a22694b25250705fac`, with the [Food custody and native receipt-link clarifications](MISSION-CODER-G21-HANDOFF.md). It is not yet compiled or validated. The optional [Station Aid pack](mission-packs/station-donation/manifest.toml) implements the complete `PROJECT-SPACE-G21-1` family: 500/1500/3000 CR or 1/3/5 tonnes Food, one local standing point, no cash reward, journey or deadline. Values and 3600 loaded/unpaused-second board cadence are explicit project estimates/policies from the [authority snapshot](mission-specifications/g21-research-authority.json).

Schema2 gains an optional closed `[pledge]` declaration with `profile`, `provider`, `title`, three `creditAmounts` in integer decicredits and three `foodTonnes`. Provider equals its pack ID; a pledge provider requires the existing main-station board, local3600-second cadence, native durable commands and story support, and cannot be parent-only or own/adopt campaign children. Generated parameters are exactly `difficulty`, `variant` and nonzero UInt32 `profile_seed`; native amounts come from the declaration. Six fixed keys and native board terms are checked before generation can escape. Native board seed low32 bits use the source default when zero, with no random offer selection.

`ContractAcceptanceQuote` carries typed read-only pledge terms and a transient review token. The existing Donate confirmation stages a native `ScriptPledgeAdmission` only in its candidate Game. The accepted handler may record its milestone/journal then issue `{op="pledge.commit"}` with no other fields. Native code checks the exact instance/board/offer/content/event/context/resources, debits full actual cash or native sellable Food, records local standing and the immutable pledge receipt, and invokes validated successful finish. No additional command after completion is accepted. The caller requires genuine completed evidence before publishing acceptance; missing, delayed, faulting or incomplete proposals retain the original offer and property.

Standing is keyed by stable provider plus actual galaxy/system/main-orbital station identity. The existing missions chunk retains a bounded `ScriptPledgeLedger`; no eviction or replay-evidence truncation is allowed. Receipt validation checks exact native offer identity/epoch/seed/content/declaration, original/donating/credited stations, full before/after money/Food/standing arithmetic, accepted-event sequence/context and successful completion linkage. Issuer standing is the complete retained0-based receipt sequence. Every ordinary station in charts0...7 and systems0...255 is in scope; synthetic Plugh256 is explicitly unsupported, without widening generic contract destination bounds.

An optional native `ScriptInstance.pledgeReceiptID` links each completed pledge to its exact same-instance ledger receipt in both directions. Active/failed/abandoned instances cannot carry it. The marker survives quote normalization, hull/content changes and terminal saves. Formats below20 reject either ledger or marker after decoding the actual missions chunk, including empty/deleted/foreign/missing-link contradictions under recomputed hashes. These are bounded internal consistency checks, not authentication against coordinated deletion or rewriting of every related evidence field.

Food remains an ordinary native commodity. Current `sellableCargo(Food)` equals raw Food because the base has no separate Food reservation API. Protected schema1/schema2 payloads and passenger/hold reservations stay separate and never count as Food, even if a payload is named food. Future real reservations flow through the same native getter. Assist flags never create a real pledge balance or missing goods. Source tests prepare starting resources explicitly and separately exercise an actual market purchase inside an isolated trial.

Contract-page proofs retain generation, review identity, selected/visible targets, resource/source availability and viewport/scroll layout as compact digests. They use the existing1024 decoded/1400 base64 limits and successful post-draw capture. Same visible detail supports action focus then confirmation; unseen/replaced/scrolled/resized/loaded controls do not authorize a different payment. Legacy coordinate-only packets have no payment fallback. Trusted runtime APIs retain native final quote revalidation.

Pledge trials create an isolated unaccepted board review with Back selected; ordinary board trials retain existing initialization. Save/Load/Restart/Return keep the established namespace/calendar/epoch barriers and live commander isolation. Completed donation rows show native receipt/standing details read-only, including when original content is missing. Saved contract rows remain ineligible for a fresh trial; the separate provider template is the supported trial entry.

Full exact commands, input hashes, timings, coverage, leaks, original renderer images and remaining limitations will be recorded after acceptance, followed by Researcher owner review and central integration.
