# Alien ownership and world history outgrow ordinary save pools

Alien attachments and their upgrades need permanent source claims, retained unapplied upgrades, uncapped lifetime receipts and large hull transfers. The ordinary salvage ledger and a single JSON save collection impose unrelated lifetime limits. Moving only collected items leaves inspection, work and pending issuance behind those gates.

A per-item upgrades array, a transfer command containing every item, a flat page manifest or a depth/page-count limit merely moves the same failure boundary. Original source facts and EMPTY outcomes must also remain fixed across reloads.

The original planned item identity is not necessarily its issued identity: the shared allocator emits structural material and commodity chunks before later technology. Storage must authenticate that actual mapping and preserve the ordinary collision domain when the native runtime separates alien custody.

## Acceptance

- Separate typed original plans/progress/world custody, source evidence, physical attachments, unapplied upgrades, individual receipts and bounded command headers.
- Bound each parser/page allocation without capping total history or tree depth.
- Reproduce original plans from their retained seed and all original source facts; retain exact original-plan progress to reconstruct actual issued lot identities.
- Enforce owner, source, command, receipt and world joins; preserve retirement, applied-upgrade claims and terminal world custody permanently.
- Stage immutable content-addressed pages with strict byte/hash/tree validation, no-follow descriptor access and durable authenticated page reuse.
- Integrate actual actor collection, private authority, dock/PLUGH operations, live effects and the complete versioned native save generation in the main coder's work.
