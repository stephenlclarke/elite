# Rescue Stations: package and sensitive-evidence couriers

P30 scenarios2 and2a are two retained orbital station courier variants, now ready as `PROJECT-P30-COURIER-2-v1` and `PROJECT-P30-COURIER-2A-v1`. They carry documents from an RRS waystation to the same system's main orbital station. Scenario2b is a separate [completed portable solar-laboratory profile](rescue-solar-mission-specifications.md), outside these two courier profiles. Apply [scope v4](implementation-scope.md), the [RRS board/reputation framework](rescue-escort-mission-specifications.md), [custody/station handoffs](station-handoff-specifications.md) and [crew/equipment transfer](crew-and-passenger-specifications.md). No surface delivery, walking or Frontier mission is enabled.

## Eligibility, acceptance and custody

Base2 has one board slot, requires RRS reputation>=-10 and player bounty<=50, then strict U<0.5. Its only destination is the current system's main orbital station. Suppress an offer if that station is absent or already destroyed. Variant2a replaces an eligible base2 slot when reputation>=10, bounty<=50 and strict U<0.8. Base and variant draws are separate and other variants can win the shared replacement order;80% is not a universal probability per visit. The shared board allows one accepted RRS assignment, stable seeded previews, explicit refusal and no reroll on Back/reload.

Base2 initializes reward30 credits and accepting system ID;2a initializes150 and source deadline=clock.seconds+7200 when its preview initializes. Source NO refuses while every other callback value, including NULL, accepts stage2. Project requires actual Confirm before committing unique custody or the active contract. Necessary preview/acceptance repair for2a: start the7200-second simulation deadline on acceptance, rather than ageing an unaccepted preview. Save both source behaviour and selected profile distinction. Back has no effect, never launches, and never clears another mission's reservation. A nonurgent courier acceptance does not auto-launch or refill fuel; launch remains the player's choice.

Represent one uniquely identified protected document/data packet, with zero hold footprint and zero optional-equipment cost, matching the absence of a source cargo/module reservation. It is a mission token, not market cargo, an alloy commodity or a free black-box model to scoop. It cannot be sold, replaced with purchased goods, duplicated, jettisoned or moved into surplus equipment storage. No passengers are boarded and no cabins are required. Other active missions' people/cargo and actual hull/equipment fit still constrain hull changes. Source virtual documents have no ship-death loss callback; preserve that mission token through a valid emergency escape/recovery unless the selected common escape route independently violates the system/deadline condition. Do not invent a physical crate-loss penalty from the display model.

Save accepting galaxy/system, original destination main-station identity, packet ID/holder, attempt/profile/scope IDs, source board seed and reward, typed scenario counter and acceptance receipt. The delivery event requires those identities, the current packet and actual player docking. A secondary RRS station, rock hermit, other system's main station or surface settlement cannot complete it. Project main-station destruction invalidates this specific delivery destination; no generic replacement station silently pays the job.

## Base2: local package delivery

Stages are1 preview,2 carrying documents,1000 arrived at the correct main station, then terminal handoff. The source moves2->1000 on same-system main-station docking, pays30 credits in the next mission-screen callback and invokes central success. The project records the arrival, then atomically transfers the packet and pays once on the station debrief Confirm. Reputation increases2; the scenario2 complete counter increments once. Refusing a preview costs nothing. The player can dock elsewhere in the same system and continue; the escort family's early-docking failure does not apply.

There is no source real-time deadline, no cargo quantity and no dedicated enemy wave. Native ambient pirates/police remain ordinary world traffic. Leaving the system invokes the source callback's central failure: pay0, reputation-10, scenario2 failed counter once and remove the expired mission token. The global RRS new-galaxy handler also fails accepted work. Project identity/terminal guards prevent both departure callbacks from applying a double penalty. Explicit accepted abandonment follows that same failure policy. A later eligible hourly board can offer another attempt.

After correct arrival, reopening/closing the debrief cannot create another packet or reward. Project handoff is an atomic Confirm; leaving without completing it abandons the still-held delivery, rather than carrying a portable paid-at-any-station state. A genuine repeated load of a completed receipt is already paid.

## Variant2a: sensitive trial evidence

Stages are1 preview,2 accepted,3 launched/carrying,1000 on-time arrival,1001 late arrival, then terminal handoff. First launch from the accepting RRS station moves2->3 and creates `2+dangerScale(128)` hunters, using `dangerScale(base)=floor(U*floor(1+sqrt(playerScore/base)))`. This is a single saved wave, not a kill quota. Each chooses one of the seven resolved core rrs-vicious-hunter definitions below with equal weight1, receives working fuel injectors and fuel7, and switches to the dedicated hunter script/AI. No ordinary missile is added to source-zero-missile hunters.

The same-system main-station docking succeeds only when stage3 and arrivalTime<deadline. Equality is late. Save arrivalTime before showing a screen: reading the debrief after the deadline cannot turn an already on-time docking late, and reopening it cannot reset a late result. An expiry marks the job overdue while it remains aboard; source failure is resolved on a late delivery or departure, rather than inventing a new midflight enemy wave. Time advances in simulation, including docked/refit/time-acceleration actions; no elapsed real-world offline time is added merely for loading a save. Preserve the7200-second deadline across save/reload and hull changes.

On-time handoff pays150 credits, reputation+10 and one scenario2a complete count. Optional Snoopers news has source2% probability and type1; it does not grant another reward, unlock or required dependency. Late handoff pays0, reputation-10 and one failed count, removes the packet and records the missed trial. Leaving the system/new galaxy or abandoning accepted work also pays0/-10. No source kill tally or extra ship/equipment reward exists. Surviving pursuers do not prevent a valid docked delivery; killed unrelated ships cannot substitute for the packet.

Each hunter is placed at lerp(P0,P1,0.85) plus independent uniform XYZ offsets in[-scannerRange,+scannerRange], scannerRange25600. This is neither the unshortened lane midpoint nor a three-letter local coordinate vector. Preserve the sampled world positions and identities. Validate finite, nondegenerate anchors before offering2a.
