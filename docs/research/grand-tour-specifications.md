# Lost Worlds Grand Tour: documented space travel challenge

P24's recovered GalDrivePod1.4 is an equipment distribution, not a hidden scripted campaign. The author's [GalDrivePod page](https://wiki.alioth.net/index.php/GalDrivePod#Lost_Worlds_Grand_Tour) explicitly presents Lost Worlds Grand Tour as a suggested activity: start at Adien in Galaxy6, cross to the isolated side of Galaxy7's Great Rift, acquire replacement drives, proceed from Onteised to Oresrati in Galaxy8, then use a saved portable drive to return toGalaxy1. Earlier coverage incorrectly assumed an unrecovered mission-bearing distribution was required. No such separate distribution is established by this evidence; remove that unsupported blocker. This corrects research classification, not a claim that every historical revision has been exhaustively searched.

## Source equipment and route

GalDrivePod is a pylon-mounted Portable Galactic Hyperdrive Unit, available techlevel12andabove,7500credits. Its1.4 main script temporarily changes standard galactic hyperspace behaviour to ALL_SYSTEMS_REACHABLE when a pod is mounted, restoring standard behaviour after arrival. The installation script awards a standard galactic drive if none is present; if one already exists, returns the pod rather than silently consuming it. Activation/consumption follows its source pylon AI. Preserve unique pod ownership; repeatedly selecting a hull cannot generate more drives. [Pinned O07 P24 provenance](data/oolite-pack-sources.json).

[Independent route bindings](data/challenge-route-bindings.json) establish zero-based galaxy5/system222Adienat[21,232], galaxy6/system15Onteisedat[1,251], galaxy7/system162Oresratiat[16,255]. C-compiled recovered GBA name generation and the current project Universe agree. Source galaxy navigation uses the corresponding galaxy's coordinates, not the same system index in each chart. The portable pod enables the exceptional route; an ordinary7LYjump across the Great Rift must still fail when no legal route exists.

## Explicit optional project journal

This wrapper is a project adaptation of the documented activity, not recovered historical mission code. Offer it at Adien's main orbital station with no score requirement, no fee, no timer and no cash/equipment reward. Player chooses Track tour or Back; normal trading/exploration remains available. Before departure require a standard galactic drive and at least one unused mounted/stored transferable portable pod capable of leaving the next isolated region. Show a named route prerequisite instead of inventing a standard wormhole across the rift.

Journal stages are: PREPARE_ADIEN; ENTER_ISOLATED_G7 (actual galactic arrival from Adien using the pod override); RESUPPLY_G7 (commander owns a replacement standard drive and at least one reserved portable escape pod); DEPART_ONTEISED (actual departure from system15with correct jump mode); VISIT_ORESRATI (actual arrival atGalaxy8/system162); RETURN_G1 (portable-drive installation/galactic departure); COMPLETE onGalaxy1arrival. These named milestones make the activity implementable without adding arbitrary unseen combat, a mandatory tour of all29systems or a fabricated historical reward. Optional extra visits are log entries, not completion gates.

Station services replace any place-related conversation; no planetary landing is required. Oresrati's low-tech isolation is the reason to reserve the escape pod before leavingG7. Warn in the tour panel if that reserve is missing; Back leaves the tour pending. Do not silently provide free fuel/drives or delete the user's exploration save. In the project variant a held reserve pod is visible/transferable but cannot be sold/consumed by a different action without an explicit tour-abandon choice. Once abandoned it returns to normal personal inventory. This reservation rule is labelled project design, not source equipment behaviour.

Persist activity ID, source/profile revision, starting commander snapshot reference, exact galaxy/system milestones, unique drive/pod identities, reserved consumable, chosen prerequisites, visited systems and completion event. Save/reload or ship swaps preserve the route and must not consume/recreate pods; compatible equipment transfers and persistent surplus storage use the common shipyard rules. Ordinary mission cargo is unaffected. A commander may abandon/restart this voluntary journal, but restarts grant nothing and cannot reset ship damage or fuel.

Acceptance: wrong departure system, ordinary jump versus galactic jump, real Rift reachability, missing replacement drive, reserved pod on either compared hull, actual Oresrati arrival, full circle return, reload after each consumption and unique completion. No campaign source fixtures exist because the package has no campaign state machine; the equipment scripts and verified endpoint identities are the historical evidence. This activity is ready as the explicitly bounded project wrapper described here, with native-edition route/runtime integration still requiring implementation checks.
