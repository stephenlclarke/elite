## Historical provisional schema1 mapping limits

The directly shared draft uses one UTF-8 TOML per mission, maximum256KiB, stable pack/version/minimumEngine/dependencies/capabilities and tables mission/stages/transitions/dialogs. Save key is packID/missionID. Draft capability names are state-machine-v1, dialog-v1, economy-v1, cargo-v1 and clock-v1. Only the documented typed AND predicates and allowlisted actions/events are valid; no arbitrary source scripts or file access. External packs cannot request reserved bundled encounter bindings, arbitrary NPC spawns, new AI, crew/cabins, station boards or equipment storage. Those limits keep all RRS packets dependent on additional native engine work. A smaller courier-shaped rewrite does not preserve their researched objectives.

Draft transition order is file order, at most one per mission per event, without recursive dispatch; packs order by priority then ID. Confirm rechecks stage/location/conditions before atomic transition/economy/payload/receipt actions; Back has no effects. Credits use tenths of CR, protected payload quantities use tonnes. Clock means persisted elapsed stage flight time only: it advances during unpaused flight, freezes in read-only panels/dialogs, and dock arrival precedes the next clock event. Historical wall/commander/flight timers, multiple simultaneous actors, actual station identity and equal-time ordering require explicit adapters, not silent clock substitution.

Missing packs or version/content-digest mismatch suspend intact progress/payloads. There is no guessed active-state migration or reward replay. The example is a new project courier rather than a source Elite campaign; the declared validator/install paths remain provisional until coder validation. Source and gallery/save tests remain required even after TOML parsing succeeds. Do not produce a runtime-ready label from this draft or enable an unsupported source mission merely because its stage names can be encoded.

The coder's expanded provisional reference now bounds packs to1-64stages,1-128transitions and1-64milestones, with at most32conditions/actions per transition,12000characters per dialog and stable IDs of1-80characters. Transition IDs are once-only; a loop cannot reuse an ID for another partial delivery, replacement sample or contract instance. Exact installed-version dependencies are not mission-completion prerequisites. The finance/other campaign adapters must preserve actual partial quantities, distinct retry/batch/receipt identities and parent progress through reviewed native primitives or a future supported instance model; do not truncate the source mission to fit these limits. Updated draft hashes/legacy read-adapter/save bounds are retained in the dated schema reference; final runtime validation remains coder-owned.
