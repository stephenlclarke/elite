# Localhero I: 31-assignment Harkov campaign

P22 source 1.05, dated 27 April 2008, is recovered and hashed in [legacy provenance](data/legacy-source-recovery.json). The [author's package page](https://wiki.alioth.net/index.php/Localhero_OXP) identifies the first-five-galaxies campaign and warns that the original Oolite 1.71 script is broken in later engines. This is Oolite content, unrelated to Frontier: First Encounters despite the subtitle First Encounter. No sequel or planned trilogy episode is inferred from comments.

The complete project profile below has 31 sequential assignments, not 31 different generators. [Source checks](data/localhero-source-fixtures.json) execute all 31 starting rosters and 27 additional boundary/outcome callbacks. [Mechanics](data/localhero-mechanics.json) retain all 23 AI tables, four measured model envelopes and a pinned modern engine reference. [Ship resources](data/legacy-expansion-resources.json), package P22, retain 38 definitions including paints, weapons, pods and variants; this is not 38 unique ships. All source-relative paths below are inside localhero_1_05.oxp.

## Entry, offer and campaign state

The world script permits galaxies 1-5 (zero indices 0-4), government 5 and source techLevel >7, while docked at the main station. First contact sets success count S=0, kill count 0, goal 0, bonus 0, image 0, Harkov NO and stage FIRST. The actual offer waits for the System Data screen, legal bounty <7 and fitted fuel scoops. The ordinary timer starts after 0.5 seconds and repeats every 2 seconds; logging changes the repeat to 3 seconds and is not a gameplay requirement. There is no military-laser or shield-booster entry check: those appear only in unused text/future-work comments.

Every ship definition additionally has legacy conditions score >50. The main offer itself omits this gate. Project repair requires score >=51 before offering, so acceptance cannot create an encounter whose ships are ineligible. Present internal technology indices consistently with the selected universe profile rather than silently adding one to the comparison.

Accept -> ACCEPT; launch -> RUNNING and spawn the selected roster once. FIRST decline clears the screen but does not permanently reject; launching without initial acceptance clears the provisional contact. A later COMPLETE decline sets REFUSED and resets the mission availability on launch. Successful debrief, voluntary abandonment and ordinary failure enter DATE, storing current clock.days. Further jobs become available when floor(nowDays-parseInt(savedDays)) >8: the recovered comparison uses the saved day's integer part, so the boundary is floor(savedDays)+9. Project saves that explicit absolute next-offer date; this is a cooldown, not an active mission deadline.

S is completed assignments before the next job; displayed assignment number is S+1. Success advances S once. Complete assignments 1-31, ending with Harkov captured and the governor safe. New jobs may occur in any eligible system; an active project encounter remains bound to the accepting system and station. There is no fixed named-system itinerary.

Orbital station destruction is an explicit project failure condition for station-defence jobs; the old script has no dedicated station-death branch.

## Captures, shuttles, traps and payment

Source death bonuses: GM15, GL/GLH30, raid GM20, raid GL50, general100 credits, accumulated for debrief. Ordinary member pod player-scoop adds30, leader pod50, Harkov pod3000. Scooping Harkov also subtracts40 from legacy goal and sets Harkov YES. Source pod destruction attempts Player.credits +=5 with uppercase Player, which is not the lowercase player instance; this has no demonstrated valid cash award. Project deliberately omits the defective five-credit reward and records the casualty. Never pay for despawn/removal or repeated callbacks.

Shuttle docking subtracts40, sets RESCUED, adds1000; if rounded player-to-shuttle distance <5000, adds another1000. Destruction spawns committee/governor pod, sets FAILED and adds40; player recovering that live pod subtracts80, sets RESCUED and adds200, replacing safe delivery with rescue. A destroyed/lost rescue pod makes the special goal fail. Governor arrival announcement is scheduled25 seconds after spawn, not a mission deadline.

## Failure, station custody and persistence repairs

Source early docking offers abandon or continue. Relaunch multiplies pending bonus by0.75 and rounds up, increments a docking counter, tries to regenerate missing ships, and adds difficulty ships if fewer than21 mission actors remain. After more than one such continuation launch, the next incomplete main-station docking aborts. The regenerated goal uses mixed string arithmetic, precedence-sensitive bit operations and live role counts including friendly shuttles; it is not safe persistence. Project preserves ceil(0.75*bonus), continuation count and the two-continuation limit on actual launch, but restores the exact saved roster/actor state and does not mint replacement fleets or capture opportunities on reload. Extra relaunch ships are omitted as an explicit anti-duplication repair. Loading a save is never a relaunch penalty.

Source jump abandonment only executes if the arrival system satisfies the offer geography, leaving active state stuck elsewhere. Repair on departure from the bound encounter system regardless of the destination's government/galaxy. The source has no active numeric time limit apart from Harkov's pod and trap/timer actions. No ten-minute reset is active: that block is commented out. Do not repair future-work comments into live mechanics.

All rescued/captured personnel are orbital station handoffs, with Confirm/Back and one atomic custody transfer. The original source requires fuel scoops but does not define a durable passenger hold. Necessary project estimate: reserve one cargo tonne for each carried prisoner/rescue pod until handoff; require one free tonne on ordinary acceptance and two on the final assignment if both governor recovery and Harkov capture may be needed. No free capacity expansion. Surplus personal equipment storage cannot absorb people or mission cargo; an incompatible hull swap is blocked. Friendly shuttle safe arrival is automatic, while rescued passengers are handed over at the accepting orbital main station before successful debrief. On failure/abandonment, any survivors receive a no-mission-reward GalCop handoff at the next orbital station; never delete people or convert them to ordinary slave cargo.
