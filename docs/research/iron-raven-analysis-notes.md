## Confirmed defects and required repairs

Actual-source cases confirm a stray semicolon in IR-isabella.js makes every dock callback overwrite finance phase with WIFE_DOCKED, even after completion or outside the intended identification phase. Native checkManifest does not clear stale PART/TRUE when the new manifest has no qualifying goods. incrementDefencesQuestion uses a capitalized IR_Defences_question_no in the key while its displayed string uses the correctly cased field. Invalid wife response can still advance to WAIT3. These are source defects, not intended new-game progression rules.

Loan default clears misspelled IR_load_remaining while leaving IR_loan_remaining, and both repayment paths perform unchecked deductions. Pinned OOJSPlayer calls PlayerEntityScriptMethods.setCreditBalance and PlayerEntityLoadSave.OODeciCreditsFromDouble, which clamps negative results to0: a short balance is exhausted and the source still marks the loan paid/defaulted. The earlier plain-JS mock negative result was not native balance evidence. Retain the source clamp and no repeat principal grant; do not invent a debt amount as a historical fact. Sample award success is ignored, allowing irradiation state without a confirmed actual pylon item. Actual death near the processor qualifies without a purpose-specific consignment receipt. The selected repaired graph must name and test each correction; a broad promise to handle bugs is insufficient.

SDF collection/analysis invokes useSpecialCargo and removeAllCargo. Their destructive whole-hold native semantics are already established in the pinned engine research; preserve unrelated property and use a finite protected consignment instead. Source buying a new hull erases TIPPEDOFF shipment state. The owner requires hull switching to preserve mission state and custody, so this callback cannot be copied as the project's implementation. Neither source defect authorizes equipment destruction, silent passenger removal or mission rewards on a hull change.
