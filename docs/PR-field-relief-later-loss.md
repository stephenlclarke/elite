# Preserve field-relief failure through later native cargo loss

Refs [issue 34](https://github.com/stephenlclarke/elite/issues/34). The terminal command and save validator now share one custody join for a held original batch after target destruction. A genuine later escape, ship loss or unpaid source return can retire that batch. The mission snapshot, completion receipt, settlement and clue journal remain unchanged; existing atomic native publication still rolls back rejected changes.

The join validates the actual target tombstone visit, current native visit/time bounds and loss cause/energy, then compares every original consignment field after removing only the later retirement evidence. Script flight/calendar clocks are not compared with native physical time. The tombstone stores a visit, not a physical timestamp, so same-visit event order remains enforced by the real native producer and previous-ledger comparison. No save fields or version numbers change.

Four isolated regression methods (five expanded cases) cover both loss causes, invalid cause/energy/time/visit, altered original property, installed-property refusal, unpaid return, original receipt round-trip and closed leaf decoding. Core authoring compilation and unit declaration type-checking pass. The actual Swift units run on GitHub; hosted execution and independent MBA verification remain pending. No native journey, integration, sanitizer, leak, performance or release campaign was run for this packet. The normal final release gates remain required.

This packet also composes the separately authored [issue 35 summary compiler fix](PR-contract-board-summary-timeout.md), preserving fallback order and summary strings. It does not publish a new playable app.
