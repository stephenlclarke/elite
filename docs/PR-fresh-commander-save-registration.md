# fix(save): register a safe destination for fresh native commanders

Before normal startup enters its interactive loop, the app registers an absent destination with GameRuntime if restore did not bind a writer. A fresh installation uses its absent default path; failed restore, Start New and cancelled or unsuccessful replacement selection use a distinct UUID directory. Only accepted registration changes the active menu path. Registration writes no files or preferences. Controlled launches retain their existing explicit setup. Registration failure reports the error while keeping the ordered command/frame consumer alive so explicit Open or Save As can recover; existing missing-writer durability guards remain active.

Runtime-only value fields carry the pending destination and its first successful publication receipt. Both raw and versioned writers publish a new destination exclusively: an owned staging file is opened with `O_CREAT | O_EXCL`, fully written and closed, then renamed with Darwin `RENAME_EXCL`. A racing existing destination is preserved and command publication rolls back. Cleanup removes only the staging file this attempt created, including partial-write failures. Versioned publication can retain an unreferenced candidate generation on refusal, matching existing failed-publication behavior; the old pointer and referenced generation remain intact. Accepted existing writers retain atomic replacement.

Only actual successful first publication produces the existing live CommanderFileReceipt. The ordered native command/frame consumer acknowledges that receipt with the save session; registration alone does not pretend to be a successful save. Successful Open clears the ephemeral registration, Save As replaces the writer only after success, and stale receipts cannot acknowledge a different current destination. Gallery retains its private writer and the saved parent’s value state. Existing manual save/load receipt behavior is unchanged. See [the missing startup precondition](ISSUE-fresh-commander-save-registration.md).

Dedicated source regressions cover the shared app startup and real queued launch path, registration without files/preferences, restart selection after publication, invalid and missing previous saves, actual recovered fitting in registered native flight, collision after registration preserving an existing pointer and referenced generation, failed first write, stale acknowledgment after Open/Save As, and rejection of existing files, dangling links and trial writers. The world-job failure publisher now commits its prepared candidate only after successful publication, retaining destination completion and its receipt; a failed writer retains the original suspension and physical state. Actor game-over restart carries the runtime-only destination and unacknowledged receipt into the replacement Game. Added regressions exercise the actual world-job clock-limit fault as the first publication, a subsequent write, failed-publication retry and resource conservation, restart before first write or receipt acknowledgment, and shared startup registration failure followed by actual queued Open/Save As and flight/control advancement. All pre-existing test bodies are unchanged. Source formatting, Markdown lint and whitespace checks are the only checks run for this isolated batch. Compilation, focused native/runtime execution and full CI remain pending with the canonical owner after frozen run 222 closes; no runtime acceptance or release claim is made.

README, player controls and contextual help now explain automatic destination preparation, separate recovery paths, last-successful-write preferences, native fitting/contract publication and failure refusal. Published 1.4.0 behaviour is explicitly distinguished from this development source pending final acceptance.
