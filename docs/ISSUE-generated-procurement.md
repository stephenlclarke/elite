# Generated procurement

## Motivation

The existing partial collection and contract infrastructure cannot safely bind a generated procurement offer to its actual commodity requirement. Noncourier mission-clock contracts are rejected, and the generic acceptance path would create an unsupported mission-calendar timer. A new Lua pack alone cannot provide native reward or handoff authority.

Qualified run 372 exposed a later generation defect: revision 1's fixed origin-0 rows required at least 308808 and 225864 mission seconds against their 172800-second deadlines. The genuine native acceptance guard correctly refused them. Revision 2 must filter the original ordered native route pool by each tier's unchanged deadline before selecting its frozen draw. Changing the origin, rerolling a selected route or extending a deadline would conceal that defect.

## Scope

Implement one installable procurement variant from `PROJECT-SPACE-G03-1`, using existing bounded offer parameters, contract jobs, real collection lots and ordinary settlement. Preserve G02 generation, all existing tests and legacy nil policy. Supplied freight, default activation, other generated families, native storage and save/container changes are excluded.

## Required behavior

Freeze exact native reach, seed, six separate route/commodity draws, selected route, commodity, quantity, terms and owning content. Validate the same proof on direct current container reads/writes. Materialize one declared collection template centrally. Require the actual native destination dock and fresh confirmation; preserve partial deliveries and pay once after the final real lot. Expiry and abandonment are native zero-payment transitions.

Saved partial and terminal contact facts must also join the commander's retained native world, original main-station identity, issued dock sequence and actual clock/visit ceilings. A structurally valid foreign or not-yet-issued paired receipt must fail direct container reads and writes. Genuine historical arrivals remain valid after later launches and dockings.

Keep revision 1's exact pool, original pack bytes and nine seed goldens as compatibility inputs. Existing saved boards and feasible jobs must load with their original terms; new revision-2 content must not rewrite them. The Gallery fixture must use a valid commander name and normal Gallery entry before testing isolated launch and storage. Failed quote assertions must report bounded booleans and reasons.

## Validation

Source-authoring allocations permit static formatting/lint and manifest inspection only. Earlier qualified execution reached the real paid shop, launch and dock, then refused the impossible revision-1 quotes; the Gallery fixture failed its initial save because its name exceeded 16 characters. G1 subsequently compiled and executed the revision-2 correction in run 374. The native fixture keeps normal actors, clocks, resources and route controls and fails if a fixed market/route premise is unavailable. Focused execution, sanitizer/leak/coverage and `make ci` remain G1-owned.

Qualified run 374 passed the market/final-payment, Gallery and generation/compatibility checks, but found an incorrect Back input and flight-liveness failures. Procurement defaults to Back; the fixture's Right key selected Confirm and legitimately abandoned the job. The test must use the genuine default Back and retain full Commander and file equivalence. Captured flight issues retain only `live == false`, so their cause is unproven. One opt-in diagnostic on the original partial-delivery scenario will observe the last live pre-advance and first failing post-advance scalars without changing any controls, resources, traffic, route or fatal guard. Its output is limited to one 4096-byte record or a bounded refusal, including frame/revision stamps rather than a fabricated collision count. Qualified run 376 subsequently passed Back with full Commander/file equivalence and reproduced finite energy loss during the original partial-delivery flight. Its single 1734-byte diagnostic does not identify the fatal attacker or weapon.

Root permits real defensive preflight before selecting the desired main-station AUTO target, followed by genuinely unattended docking. Only the original partial-delivery travel opts in. Initial paid setup, board, row, route, markets, fit and budget remain fixed. Preflight authenticates live current engagement intentions, then permits a front-laser request only for a wanted threat outside every current station no-fire radius and matching the nearest forward mesh hit. Clean or obstructed threats receive real braking/tracking without firing; real damage, police response and ordinary time/resource costs remain. Preflight and AUTO share the original 3000-step bound, and a later threat cannot restart preflight after the AUTO lock. There is no promise that the fixed loadout survives normal combat.
