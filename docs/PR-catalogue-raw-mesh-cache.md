# Reuse immutable exact-ID physical catalogue meshes

New `ShipRawMeshCache.swift` extends ShipCatalogue with one static immutable dictionary built from its existing validated `all` records and each record's unchanged `design.rawMesh`. The catalogue-ID branch in `gameplayMesh(for:)` returns that value. Swift's once-initialized static storage and Mesh's checked Sendable immutable arrays provide sharing without a mutable registry or per-frame I/O. The tradeoff is retaining raw adapters for all bundled ships and their one-time construction at first use.

Alien ordnance, current station, salvage-lot scaling, mining-rock scaling/appearance, unknown-ID fallback and all beam code remain unchanged. No showroom normalization, coordinate conversion, asset/model change, Game/Commander/layout change or test budget change is included. ShipCatalogue, appearance and asset files remain untouched for their owner.

Validation is focused diff review, strict Swift formatting, Markdown lint and whitespace checks only; no compiler, native, test or profiler job was launched. Existing central checks include `MissionNativeBridgeTests.realRoundedCapitalAndFighterFacesPreserveNativeZeroRayAndAcceptSweptQueries` (actual raw physical geometry and real ray/sweep hits), `ShipTextureAssetsTests.selectedSourceBindingsSurviveMeshNormalizationAndPlayerScaling` (authored texture/UV adapter conservation), and existing alien-missile/physical-rock branch tests if G1 needs branch qualification. No mirrored cache test or broad catalogue rerun is added. G1 chooses one safe coherent build opportunity and independent validation; retained memory, startup cost and runtime benefit remain unmeasured.
