## One confirmed durable operation

Reuse the existing station Contract Board, `ContractAcceptanceQuote`, `confirmContract`, native accepted instance and transactional publisher. The player selects a tier/variant, reads exact terms and deliberately chooses **Donate**. The underlying enum action may remain `.accept`; label it Donate only for pledge offers. Back is the default. The same confirmation accepts the identified offer, debits the full resource, increments the exact local standing, writes its typed receipt and completes the mission in one durable generation. There is no escrow, second contact screen, loan or accepted delivery journey.

Generate six fixed keys such as `credits-1` and `food-3`. Every offer pins profile, difficulty, variant and seed, with zero reward/deposit/failure reward, no refund, duration0 and destination equal to its actual offering main station. Reuse the existing board group and provider/cache/epoch identities. The generator proposes no commands. There is no random amount, destination or composition to select. Preserve the native board seed and a nonzero UInt32 profile seed; expose `board_seed_u32` from the existing native seed's low32 bits, mapping zero to the source default `0x6D2B79F5`. Store that value in frozen parameters. No xorshift draw is needed for six fixed user-selected offers; do not substitute an LCG random selector or reroll during reading.

Candidate rows with insufficient resources or exhausted native budgets may remain visibly unavailable with a reason. They are not actionable offers. Changing money/Food can change eligibility without changing an offer's identity, terms or epoch. Never use incomplete stock as a smaller pledge. Generating, selecting, quoting, painting, scrolling and Back change no authoritative money, goods, standing, accepted state or completion receipts. Existing explicit Decline consumes only that unaccepted offer, with no debit/reputation/penalty. An instant completed donation has no playable accepted-but-unpaid interval; transaction failure retains the original available offer. Do not invent an abandonment charge or refund.

Only actual ordinary Food in `Commodity.all`, unit `t`, and the current native `Commander.sellableCargo(foodIndex)` quantity qualify. Do not count protected mission payloads, passenger accommodation or other reserved hold space as Food. Native quantities remain integer tonnes; credit arithmetic remains integer decicredits. Cash assist flags are not an infinite real balance. Food/hold assist flags do not create goods. Cash equal to the requirement and Food exactly sufficient both succeed; one unit short refuses the whole operation. Food donation leaves cash unchanged; credit donation leaves cargo unchanged.

## Proposed closed API

Extend the existing schema2 manifest with one optional `[pledge]` declaration and proposed capability `station-pledges-basic-v2`. Suggested exact fields are `profile`, `provider`, `title`, `creditAmounts`, `foodTonnes`; the selected pack uses the profile/provider above and the two exact three-element arrays. Provider must equal the pack's own ID. Validate finite bounded strings, three positive integer amounts of each kind, valid native money/Food bounds and declared capability. Require an existing board and prohibit parent-only/child adoption for this instant pledge provider. Do not add arbitrary reputation-set, commodity-edit or financial-product commands.

Generated offer parameters are exactly `difficulty` (1...3), `variant` (`credits` or `food`) and `profile_seed` (nonzero UInt32). Native code derives the amount from the pinned declaration, never from Lua text or an arbitrary command amount. The offer's origin/destination, fees/rewards/duration and profile parameters must satisfy the pledge contract before it is actionable. The selected resource/tier, provider/station, original board/offer/version/digest/epoch, real resources, native standing and commander context freeze in the quote.

Add one command, `{op="pledge.commit"}`, with no other fields. It runs only for the real `mission.accepted` event of this native board confirmation, with an exact temporary native admission context. The Lua accepted handler may ensure the declared milestone and append its journal before that command. Native code commits the pledge and invokes the existing successful-finish validation itself; it does not leave payment dependent on a later story flag. `mission.finish complete` for a pledged pack must also require its genuine native pledge receipt. The generic command is not a terminal-parent service or an arbitrary reward right.

Before invoking the accepted handler, `acceptContract` prepares an internal value-only `ScriptPledgeAdmission`: exact instance/board/offer, content/declaration/parameters, provider/station/context and quoted cash/Food/standing before values. It belongs only to the candidate Game while this transaction executes. `pledge.commit` requires the exact admission and actual accepted event/cause, revalidates location/resources/standing, and refuses any prior Lua command that changed those quoted assets. It never trusts `data`, narrative flags, labels or a caller-supplied price. Clear the admission before returning. No transient admission can be saved, reused by another root or survive a failed proposal.

After `acceptScriptMission` returns, the pledged-contract path must verify actual completed outcome, matching native pledge receipt and settled zero-payment contract. Otherwise reject the whole acceptance. This is essential when event dispatch is deferred, the64-event drain budget cannot reach the new accepted event, or the handler faults/omits its pledge. Do not publish a pending accepted job and donate later without its original confirmation.

Duplicate same-offer confirmation uses the existing accepted-instance identity and returns its original result harmlessly. A different instance cannot claim that receipt. No second debit, standing gain, new instance, reward or automatic acceptance of the next row is allowed. Any unsupported command after the pledge/finish, missing milestone, failed validation or filesystem publication rolls the entire original proposal back.
