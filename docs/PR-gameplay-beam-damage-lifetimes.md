# Separate gameplay NPC preparation and fatal-only player diagnostics

The gameplay NPC beam now calls private cold preparation, origin, impact and completion phases on the same live Game. Two private synchronous non-Sendable reference objects retain only the original preparation values and origin. Full physical actor/target/contact query temporaries finish before damage recording. There is no Game candidate, new rollback boundary, actor/task, public API or retained reference back to Game. Existing legacy and gameplay producers keep their distinct behavior.

| Phase | Preserved contract |
| --- | --- |
| Query and admission | Same first body index, EMP/cooldown/energy/resource guards, supplied context target, current pose projection, mining/pulse range and heading, nearest occluding source-excluding ray and intended-target test. The flight snapshot is still copied **before** the intended-target guard and native preflight. No new actor/station rebuild or context substitution is added. |
| Native preflight and origin | Same laser selection and native preflight, then the same origin allocation for the captured real emitter. Full query/preflight values unwind before origin/impact phases. Origin refusal adds no rollback. |
| Impact | Same contact script branch, native apply and immediate receipt projection. Only native apply refusal restores the original flight snapshot and skips completion. Ordinary hit's optional result remains ignored. The original emission-position query remains at each impact argument, through a cold projection returning before the native kernel opens. No new geometry, law, entitlement or source guard is introduced. |
| Completion | Use the **original captured index**, without reselecting the body, for the same cooldown, one energy debit and heat 10; finish the same emission last. Mining/pulse cadence and damage remain unchanged. |
| Shared player hit | Original world-point query, positive-energy guard, hit recording and damage application stay in order. Only if that damage leaves `energy <= 0` does a cold helper execute the original fatal block. Revision, original incident/owner, laser/mount/legal/player/body queries, duplicate-owner handling, exact log/privacy fields and final destruction recording retain their original sequence and values. Return the same initial hit incident. |

The fatal block is moved verbatim except indentation. Its original `origin`, world position and other arguments are passed explicitly; no attribution is inferred from a replacement source. Nonfatal hits do not enter that helper. Existing `recordCombat`, station rebuilding, mission entitlement, law and shared damage kernels are untouched. Classes form a local acyclic chain; consumed contact/flight values remain private and synchronous. There is no global Game/Commander layout, snapshot publication, validator, timeout or concurrency change. Cold source boundaries are not a measurement or guarantee of emitted stack margin.
