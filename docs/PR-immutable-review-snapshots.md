# refactor(contracts): share immutable review resource snapshots

Contract and RRS quotes now privately retain a module-internal final `CommanderSnapshot` with one immutable Sendable Commander value. Their existing `resources` getters still return the captured Commander value. Explicit internal initializers preserve the original labels and defaults, including optional previews and contract review tokens. RRS tokens remain generated per quote. Mutable simulation remains owned by GameRuntime, and Game/Commander remain value types. See [the measured layout problem](ISSUE-immutable-review-snapshots.md).

The actual stale guards still compare `quote.resources == commander.contractQuoteResources`; no identity, partial projection, hash or JSON substitute determines acceptance. Every native station capability, epoch, price, capacity and transaction check remains. Review storage is ephemeral and excluded from existing save projections, so no Codable schema or saved Commander field changes. The shared class has no mutable property, unchecked Sendable conformance, lock, callback or reference to Game/GameRuntime; later Commander mutations use ordinary value/copy-on-write semantics.

New regression coverage mutates original and returned cargo arrays, equipment sets and nested station-resource dictionaries while checking both quotes remain frozen. A real generated contract rejects changed property without altering that property or the old review, then accepts a fresh review. Existing genuine RRS stale-review cases gain cash and cargo variants, requiring a genuinely allowed original quote and retaining Commander/body conservation. These cover compatibility and stale authority, rather than treating smaller storage as permission to weaken comparisons.

Strict Swift source lint, Markdown lint and whitespace checks pass. Independent source review, compilation/execution, new instantiated type-size measurement, renderer refresh and complete maintained CI remain pending. Old metadata and debugger evidence are retained; this layout change is not yet a crash-resolution, memory-leak, threading or release claim.
