# fix: distinguish escape pod protection from rescue permission

## Behavior and implementation

Genuine EMP escape pods retain their generic protected actor membership while their authenticated native rescue facts become available. A small internal, nonpersisted option set derives the exact five reasons in the existing generic protection projection from the current body. The builder still protects exactly the same actors. The rescue helper requires its sole reason to be the pod's own EMP crew identity and requires that the actual context includes that protected actor. It keeps every original producer and custody proof, explicitly rejects orphan blackjack identity, and refuses independent naval, blackjack and mission reasons.

This exception applies only to authenticated EMP pods. It does not reinterpret RRS people, accept a flat protection set as rescue authority, or permit public selection facts to mint custody. No persisted protection or context fields change. The actual actor capture seal, single-person admission, resource and aperture checks, private candidate publication, failed-write gate and explicit-save retry remain unchanged.
