# Navigation and trade practice: native vertical slice

## Required behavior

Translate the approved `l337.training/navigation-trade` entry in `original-missions/original-families.toml`, following the full original mission engine contract. The tutorial confirms real fitting and one free tonne, buys one stocked legal commodity, verifies the player's selected reachable journey and actual fuel debit, sells that identified tonne at the selected destination, then requires an actual return to the issuing training berth and confirmed reception. Actual market losses qualify; the tutorial invents no reward, sale price, refund or profit. Its first success grants only `navigation-trade-family-trace`.

## Authority and scope

The translated runtime manifest and Lua are separate from the private design schema. Exact executable bytes have a native digest pin. A small immutable native binding identifies the issuing/training world and selected destination; it is neither Codable nor public, saved authorization, a mutable registry or a predecessor-world alias. Production binding resolution is deliberately unavailable until the original catalogue is installed. The public mission list cannot offer this tutorial yet. This is source and engine progress, not a playable original-world tutorial claim.

Native receipts retain owner, instance and unique operation identity, confirmed fitting/capacity, contact context, actual stock/cargo/cash changes, admitted journey operation and fuel debit, destination docking identity and final training reception. Lua cannot create trade evidence or economic rewards. Cargo balance, generic events, Boolean docking, an unrelated sale, cancellation and replacement cargo after loss cannot complete the tutorial.

Confirmation reserves one tonne of hold capacity. Actual purchase transfers that same reservation to one real ordinary cargo tonne without double mass. Generic sale, collections, donations and Auto Trade cannot consume its protected custody. Explicit cancellation releases surviving cargo and capacity without recreating stock or refunding money. Escape records actual loss before cargo is cleared. Retrying uses a new instance and real available stock.

Ordinary fitting/stock/range refusals and premature reception acknowledge and remove the rejected input without committing proposal effects or suspending the practice. Reopening the contact supplies a fresh confirmation; replaying the rejected sequence is a no-op. Corrupt state and script faults retain the existing failure path.

The existing actor transaction and filesystem publisher commit cash, cargo, stock, evidence and any first-success clue together. Internal fixture binding parameters thread through that same barrier; there is no alternate transaction engine or test publisher. Public production input/load cannot accept fixture authority.
