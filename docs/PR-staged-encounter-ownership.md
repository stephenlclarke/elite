# Join encounter ownership between commands in one private candidate

When a handler returns two `encounter.ensure` commands, the first command can admit native bodies before the command loop installs their owned-encounter record into the candidate's Commander. The second admission's existing physical-scene validation resolves real ownership through `currentMissionActorDescriptor` and rejects that incomplete join. The original actor-admission fixture consequently retained no cohorts after the proposal rolled back.

The change stages `next` into `candidate.commander.scriptState.instances[next.id]` immediately after a successful encounter request. This joins the actual native bodies and their actual retained owner inside the private proposal. It does not publish the candidate or grant new admission authority. All subsequent commands, final Commander and queue limits, and the existing publisher still have to succeed before `self` changes. The source, installed-content, native scene, condition and legacy-provenance guards are unchanged.

The actor-admission fixture now reports an actual suspension reason when deployment fails. A new regression uses the real handler and native admission path, followed by an undeclared second encounter. It requires whole-Commander conservation except the intended fault suspension, unchanged bodies, body cursor and simulation randomness, and no escaped owned or native cohort. Its fixture factory completes before the private inout verification creates its comparison values. All original actor-admission test bodies are retained.

The separately affected destruction test already proves actual retained destruction and zero player kills. Native removal deliberately queues `actor.destroyed` with draining disabled. The direct test now checks both real queued envelopes and calls the actual dispatcher before its original report-phase assertion. Physical destruction, bounty attribution and production event delivery remain unchanged.
