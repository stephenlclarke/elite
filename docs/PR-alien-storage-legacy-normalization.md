# Add honest normalized legacy salvage records and conservation checks

## Result and implementation

Older saves cannot explain every missing issued fragment. This change represents that absence as an immutable, non-rewarding `legacyUnavailable` claim instead of inventing a collection receipt, destroyed outcome or historical timestamp. Original pending and stored evidence retains its exact physical lot and allocator identity. Explicit stored-property migration remains distinct from a new scoop.

`AlienStorageLegacySection` preserves the exact seed, plan, original progress, optional partial work and damage membership, ledger-wide last operation, and distinct section/wreck destruction facts. `importedAt` describes only the actual current import observation. No old inspection or issuance timestamp is synthesized. An absent partial-work entry remains absent even after a completed earlier batch.

`AlienStorageLegacyLot` records one original emitted identity and origin. Pending claims join the exact exported lot, offer and binding. Reserved stored claims join a current explicit migration view; attachment and upgrade definitions are validated separately. Ordinary stored technology remains joined to actual old inventory. Known settlements and unknown outcomes are terminal and cannot create new property.

`AlienStorageLegacySettlement` stores each original command, revision, action, value, optional binding and item count once. Independent `AlienStorageLegacySettlementItem` records preserve each complete original lot at its exact original ordinal. Claims reference the header and item IDs. The full ordered proposal is reconstructed and compared with actual transient export evidence. Cross-section items remain audit evidence and do not grant claims or property to sections that have not been imported. Existing identical settlement records are reused across imports; conflicting identities or metadata refuse.

`AlienStorageLegacyValidation` checks exact emission conservation, current-custody partitions, original settlement reconstruction, migration joins and immutable history. Transfer validation removes exactly the section's pending custody and reserved stored migrations, retaining ordinary stored technology and every original settlement. Inputs are immutable values and validation performs no native mutation or I/O.

## Shared dependency and integration

G1 supplies the agreed checked-Sendable `SalvageSectionEmissionView(seed:plan:progress:)`, with throwing `validate()` and `emissions()` methods using `AlienStorageError`. The view proves the original allocator independently of native timing and current work completion. This slice neither implements nor stubs it and never constructs a synthetic `AlienStorageWorldPlan` or copies the allocator.

G1 must add these records to existing world/index/codec/cache/replay paths, enforce global identity/section/source/operation uniqueness, and join pure migration views to actual commands, sources and properties. The sealed native export must authenticate the complete original semantic ledger state and current scene, not merely its revision: real pose updates can leave that revision unchanged. The actor must stage old-custody removal, new ownership, scene census and V27 publication in one private candidate. Failure preserves live ownership and custody.

Imported sections, lots and normalized settlements remain immutable. Post-import cutting uses genuine new work budgets and the original reset after each eight-item release batch. Post-import movement, collection and ordinary stored consumption use linked current continuation/terminal records with actual new observations and operations. They do not overwrite original pending, retained-ordinary-stored or settled evidence. Native routing must prevent the old backend from consuming or issuing the same source again.

## Page representation and compatibility

A claim contains two settlement UUID references rather than a nested proposal. Each settlement item contains one original lot, never a 128-lot array. There is no new total-settlement, section, record, page-count or history limit. The item-count check retains the original supported per-proposal inventory bound; it is not an encoded-byte proof.

The existing page packer bounds encoded bytes and splits entries independently of its entry count. The authored maximum-proposal fixture checks individual normalized record sizes with conservative wrapper headroom; this is not actual codec execution or a universal page-fit result. G1 must verify actual integrated page encoding for supported original single-lot, binding and plan shapes. If a supported original value needs further normalization, the representation must be split rather than making that old save newly unmigratable.

Current game capability, command enums and save schema remain unchanged in this source slice. No runtime acceptance, GUI result, reward delivery or new native authority is claimed. Related motivation is in [ISSUE-alien-storage-legacy-normalization.md](ISSUE-alien-storage-legacy-normalization.md).

## Validation

The authored tests use the original deterministic producer, collection and settlement methods, then decode the retained old allocator and custody values. Cases include structural serials before reserved items; tonne, kilogram and gram chunks; EMPTY and discarded technology; genuine old operation zero; partial work before and after plan inspection; a nonterminal eight-item release; collected commodity without a receipt; exact offer joins; actual stored attachment/upgrade and ordinary inventory transfer; parent death with pending fragments; a 128-item multi-section settlement; corrupted ordinals and metadata; and terminal-history preservation.

Only formatter/parser, scoped Markdown lint, whitespace and source ownership audits are permitted for this handoff. Compiler/typecheck/test/native/media jobs, CI, push and PR actions are reserved for G1 after source review. Authored tests are not reported as passing tests. Coverage and whole-app acceptance remain outstanding.
