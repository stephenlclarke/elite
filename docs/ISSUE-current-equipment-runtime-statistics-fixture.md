# Ineffective runtime-statistics fault in current equipment regression

Equipment group 484 completed without a crash and retained seven passing methods. In the nine-case current-state refusal method, only `runtime-statistics` recorded two absent expected throws. This isolated finding does not invalidate the other accepted methods or qualify unrelated cohorts.

The fixture assigned `fuelStorageUnits` above its historical maximum after current equipment preparation. Its setter writes a legacy backing count, but the getter derives the actual count from fitted inventory whenever that inventory exists. The mutation therefore did not create the malformed effective runtime statistic the test intended. Rejecting that accepted state or tightening valid upgrade bounds would change production semantics to satisfy an incorrect fixture.

Keep the case and both refusal/rollback checks, but place an actual finite statistic in the existing owned navigation component whose effective fuel cost exceeds safe Int conversion. The generic component remains legal; the existing runtime safety validator must refuse it before either current preparation or migration can publish anything.
