# Render a sunlit hemisphere and stable economy-based night settlements

PlanetPreview now carries a typed PlanetLighting and a separate PlanetNightProfile derived from the actual inspected StarSystem. PlanetPalette and its economy-based daytime colours remain independent of government. The new night profile provides bounded economy/technology settlement coverage, warm emission, local smog scatter and ordered government brightness. Anarchy uses 8% of the otherwise matching Corporate night intensity; high-tech agricultural coverage remains sparse. All coefficients are project-authored visual choices and do not reuse combat hostility rates.

PlanetLighting distinguishes stable chart presentation lighting, a real sunlight direction and an explicitly unlit scene. Its flight(viewPlanet:viewSun:) API receives both positions after the same cockpit-view transform. The displayed sphere normal's positive z points towards the observer, opposite positive camera depth. A camera-facing sphere basis projects the actual planet-to-sun direction consistently, including off-axis disks and front/rear/side views. Missing or invalid sunlight returns unlit; it never invents a flight sun.

PlanetSettlementMask creates two immutable 256×128 Float maps on a cache miss: land emission and a wrapped local blur for scatter. Stable spherical noise supplies clustered cities, coastal emphasis and sparse connecting corridors. Ocean, ice and high mountains reject direct emission. Its key contains identity, sea level, ice and economy/technology coverage; government intensity changes do not move settlements or rebuild the mask. Height/cloud terrain generation is unchanged, apart from making the existing pure noise helper module-visible for the new presentation mask. Neither terrain nor settlement generation consumes simulation RNG.

CPU and Metal use the same signed normal-to-sun illumination, dark ambient floor and soft twilight fade. Clouds attenuate direct city emission; nearby settlement blur alone supplies warm smog scatter, preventing a uniform night haze. Settlements use the same longitude, latitude and rotation as terrain. Night lights fade out on the day side, and the atmospheric rim follows sunlight while preserving premultiplied alpha and transparent space. Day-side pixels skip night sampling when their twilight factor is zero.

Both image caches include the complete light and night profile. The existing eight-entry terrain cache remains identity-only; a separate settlement cache is bounded to eight immutable maps. GPU terrain buffers remain identity-only, with two extra mask buffers uploaded only when their mask key changes. Named uniform slots 0–30 are preserved and nine light/night slots are appended; buffer bindings 0–3 are preserved and mask bindings 4/5 are explicit. Existing one-time asynchronous compilation, main-actor resource ownership and immutable published image bytes are unchanged. No new unchecked Sendable conformance or concurrency escape is introduced.

## Required central integration

Coder 1 owns Display/CelestialRendering. For the actual planet preview, locate the current real sun and pass lighting: PlanetLighting.flight(viewPlanet: game.viewPosition(planet.position), viewSun: game.viewPosition(sun.position)). Missing sun must pass .unlit. Chart/data callers retain typed .presentation lighting. This worker deliberately does not edit Display or Game. A new actual-flight test requires that hook in all four views and checks moving-sun counterexamples and missing-sun behaviour; it is not satisfied by the existing presentation-only call site.

The direct GPU image API retains source compatibility for callers without night data through explicit uninhabited/presentation defaults and one immutable empty mask. Production PlanetRenderer passes actual profiles and cached masks. The existing all-eight-economy parity test now passes those actual inputs. Direct benchmark/experiment callers that need inhabited night rendering must likewise supply lighting, night and settlements rather than relying on compatibility defaults.

## Validation and limits

Six new source tests cover daytime government independence, bounded economy/technology/government counterexamples, high-tech Anarchy dimming, sparse agriculture, seeded habitable-land masks and seam/reopen stability, towards-observer camera signs in all four views, night/light/rotation cache invalidation, transparent/opaque pixels, named uniform ABI, cloud attenuation and local scatter, and the actual pending flight-source hook. One new gated GPU test compares 32 economy/government/technology/light cases against CPU and checks previously published frames remain immutable. The existing gated 72-case eight-economy comparison retains its colour and alpha tolerances.

Only strict Swift formatting lint, scoped Markdown lint and whitespace/source checks ran. No compiler, typecheck, tests, native process, image generation, media, performance or CI job ran. All new source is uncompiled and unexecuted. G1 owns actual flight-source integration, gated CPU/GPU execution, compact/fullscreen visual and frame-pacing proof, renderer-generated repository media and required final gates. Source preparation is not native acceptance. See [motivation](ISSUE-planet-night-lighting.md).
