# Route mission pack files and folders through existing providers

Install Mission Pack now accepts a legacy TOML file or a complete schema 2 folder. A shared input router selects the existing provider by actual URL kind; legacy reads, bundled dependency checks and installation behavior stay in their original paths. Folder validation and installation reuse `ScriptPackLibrary` and `GameRuntime.installScriptPack`, including protected Lua evaluation, resource/path checks, immutable content verification and trial restrictions.

The CLI prints the original legacy success line for files. For folders it reports content identity, unsupported capabilities and declared `id@version` requirements, while explicitly leaving runtime availability to the commander and installed content. Installation notifications now use the existing availability predicate, so missing dependencies or a required save cannot produce the supported-content prompt. No capability, dependency, save or acceptance gate is bypassed.

Three new methods declare eight source cases covering legacy output, protected modules and honest unavailable-content reports, invalid inputs without fallback, separate installation destinations, idempotent folder content and continued missing-dependency refusal. Static formatting and documentation checks are the authoring scope; compilation, execution, native picker acceptance and actual CLI smoke remain pending G1. No validation job ran here. R21 and full engine readiness remain incomplete; migration dry-run, isolated hot reload and general scenario/replay tooling are unchanged.
