# Weight new ring presence by economy and preserve recorded mining history

AsteroidBeltPresencePolicy defines the approved project balance: economies 0 through 7 use 80/80/80/60/40/20/20/20 percent likelihood, retaining the system-7 starting destination exception. AsteroidBeltDefinition uses the same deterministic identity/seed sample and keeps the original uniform policy available explicitly. Geometry, orbital radius, rock identities, contents, quantities, depletion masks and cargo fragment namespaces are unchanged.

Fresh MiningLedger values start at generation 2 with weighted presence. Decoded generation 1 or absent-generation ledgers retain their original presence until an explicit atomic migration receives actual current/history StarSystem pins. AsteroidPresencePin computes the original presence from that system and galaxy. requiredPresencePinSystems includes terminal and ring-terminal history, partial rocks, pending ore, offers and bindings. Migration requires unique valid pins covering exactly all history plus the current system, including current absence; ring activity requires a present pin. Only after all checks succeed does it store the overrides, preserve independent legacy-cluster retention and advance the generation. Repeated migration preserves the original pins. Old absent-generation ledgers retain their legacy field geometry after migration, including their depleted and pending source identities. PLUGH system 256 is supported.

The ledger resolver checks saved overrides before the selected policy. Charts and compact details call that resolver. MiningFields has an explicit resolved-ringPresent overload and retains a documented uniform-policy compatibility overload for existing producers until central integration. The decoder bounds and checks unique override identities, generation/profile consistency and false pins conflicting with recorded ring activity. No mining records are cleared during migration.

## Required central integration

Coder 1 owns the actual load and new-visit migration boundary. Before rebuilding fields, resolve requiredPresencePinSystems to actual systems in their respective galaxies, construct original-policy pins, and pass historical pins excluding the current identity. Supply the actual current StarSystem pin separately. Then pass ledger.ringPresence and retainsLegacyFields to MiningFields. Never migrate using the chart target or a newly selected destination as the saved current world. Completed generation-2 migration is a no-op, so future visits do not accumulate arbitrary pins.

EncounterContext and TrafficIntent must carry and use the same resolved presence and legacy-cluster context. Their existing compatibility entry point still uses uniform presence in this source commit; actual NPC/flight consistency is pending those owned hooks. Whole-save header version 26 or later, raw future-key/null checks, downgrade guards and actual saved-world proof also belong to Coder 1. Generation 2 must not be emitted under an older header. Existing canonical MiningLedger resource-admission preflight additions are outside this commit and must be preserved during integration.
