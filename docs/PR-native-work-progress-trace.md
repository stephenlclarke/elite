# test(salvage): trace bounded native work progress on request

The remaining native multi-batch test can write at most six JSON lines directly to standard error, prefixed `ELITE_NATIVE_WORK_TRACE`, when its process environment contains `ELITE_NATIVE_WORK_TRACE=1`. The default path emits no trace. Each reached loop reports only at zero-based iterations 9 and 109, after its original work assertions, using its already computed before/after observations. The static phases are `first-release`, `second-cycle-start` and `resumed-release`. Observations contain seconds, releases, serial, pending count, damage and optional credited work; an absent optional credit is omitted by Swift's synthesized encoder. Monotonic elapsed time starts at test entry, including fixture preparation and intervening saves. Encoding failure emits a distinct error marker and supplies no progress evidence.

## Validation and compatibility

Source correspondence removes the diagnostic declarations and calls, restores the anonymous iteration variables and observation conformance, and recovers the complete original test byte for byte. Swift formatting, Markdown lint and whitespace checks are author source checks only. No compiler, test, profile or native process was run by the author. No production file, persisted schema, authority, physics calculation, budget, assertion, controls, loop cardinality or save/reload sequence changes. The executor independently reviews and builds this leaf once before an allocated diagnostic run.

## Executor diagnostic and inference limits

G1 owns a single bounded 150-second diagnostic after independent review and coherent compilation. Pass `ELITE_NATIVE_WORK_TRACE=1` to the test process through the existing owned execution path and retain its output, source and binary identity, method-start/terminal events and cleanup evidence. Do not extend the original acceptance deadline, alter stack/concurrency, or claim acceptance from this diagnostic. A full 600-second acceptance run follows only a causally supported repair.

The two points per phase show actual credited seconds, releases, lot serial and pending cardinality before/after the sampled frame. Their elapsed difference bounds throughput across the intervening 100 iterations, including all production and snapshot work. Static phase identifies the loop. Flat seconds with unchanged releases means no additional earned work at those sampled frames; release/serial/pending changes must be interpreted together. A missing later marker only establishes that it was not observed within the retained interval: it may reflect an earlier phase exit, exception, or unfinished iteration. The trace does not identify a refusing collision obstacle, distinguish individual cutter guards, prove all intermediate frames, or establish release correctness without the original assertions and method terminal. No new production cache or collision shortcut is proposed.

## Readiness extension after run 535

Each JSON record additionally contains `beforeReadiness` and `afterReadiness`, projected only at the same two enabled checkpoints from the already available Games. Each projection borrows its Game and records physical time, optional holding state, optional full controller status (including the actual clearance message), fire suspension, stored weapon display status, selected tool label, hot-session presence and last-applied-motion presence. All fields are accessible through the existing test import; no Game API or state was added. Optional holding/controller fields are omitted when guidance is absent. The stored display was already prepared by `GameRuntime.snapshot`; reading it does not invoke another readiness or collision query. Enum status text is diagnostic output, not a new stable serialization contract.

The physical-time pair distinguishes a clock that advanced from a refused or inactive frame. Controller status and holding distinguish approach/blocked guidance from a ready hold. Suspension and stored weapon status separate fresh-input, power, view, resources and target refusals. Hot-session presence distinguishes the imported cold baseline from a current work cycle. Last-applied-motion presence distinguishes accepted work/braking motion from a coast; it does not identify which motion or prove cutter admission. These are observations at the sampled boundaries, not a history of every transition inside a frame. Exact refusing obstacle, clearance and budget counters are not retained by this extension and must not be inferred from the message alone.

The executor may close its one allocated diagnostic as soon as both first-release markers are retained, using its verified owned-process supervisor and a maximum of 150 seconds. The test never short-circuits its original loops, assertions or save/reload sequence. Such supervisor termination remains partial diagnostic evidence without a test terminal or pass. No additional runtime/compiler job was performed by this author.
