# Preserve commander snapshots with smaller Game values

Instrumented actor-driven launch can exhaust the worker stack while several Game values are live. Game now holds its Commander in private, always-one-element array storage. Public read and modify accessors borrow that value; the standard library detaches it when a copied Game is mutated. This preserves nested value semantics without mutable shared-reference storage or unchecked Sendable.

The public Game/Commander API, Commander serialization, save versions, actor ownership and launch/admission behavior stay unchanged. Cargo death registration stages its allocated incident before assigning the body field, so the computed commander mutation and body mutation have separate exclusive accesses. Eligible sources already have physical NPC state; allocation count and ordering stay unchanged. New regressions cover independent nested inventory/script mutations, whole-commander replacement, snapshots retained across an actual actor XYZZY grant, and actual failed launch publication followed by successful retry and complete saved Commander equality.

The pre-change explicit nominal probe measured `EliteCore.Game` at 16,568 bytes and `EliteCore.Commander` at 7,606 bytes (7,608 stride) on this machine. The first affected compilation identified the overlapping cargo assignment; no tests executed. Post-change measurements, focused tests, affected thread-sanitizer paths, full CI, native checks and reproducible performance acceptance remain pending. No throughput, total-memory or completed-gate improvement is claimed from source review or nominal layout alone.

The next compile identified the same borrowing constraint in script-NPC velocity projection before test execution. Its existing pure world-velocity transform now finishes before the optional physical-body write. This preserves the motion basis, sole integration owner and optional physical-state eligibility. A full source audit found no further optional-body assignments whose right-hand side reads Commander; direct position, orientation and ownership assignments remain unchanged.
