# Game mechanics support audit

**Result: the audited candidate does not yet support every intended mission or game objective.** The candidate has substantial reusable mechanics and many wired service journeys. The missing work includes original mission bindings, several specialised physical operations, the complete finale and parts of the catalogue/gallery experience.

This is a read-only source audit. It compares the Meridian definitions with published `main` at `bba862c558530ea2d40d634f84fbd490d9cc3401` and the latest frozen mission candidate at `6552b68f7a146ceb79b4376d33cc8afd3f987399`. The candidate is separate from main; source wiring, passing units, playable journeys, merge and release acceptance are different claims. No game, compiler, native test, CI workflow or renderer was run for this audit. Later price/technology branches are not substituted for the mission baseline. Implementation priorities remain in the main project ledger.

## Later design resolutions, not runtime delivery

The user-supplied review is now resolved in the canonical design: all64 sources have a guaranteed independent continuity inquiry, C01 has exact8kg/final-archive accounting, C36 has a pre-offer preservation hold, and C09-C39 have31 distinct physical/interaction profiles with revised pacing. These rules live under [missions/gameplay/](missions/gameplay/GAMEPLAY-SPECIFICATION.md). None was implemented or natively tested by this documentation change. The frozen candidate counts below remain historical source evidence; the640 additional alternative recovery objective rows have zero qualified native coverage in this audit. A new implementation must explicitly bind and authorise these paths, including the continuity-service exception to finite lifetime source guards.

## Material gaps

1. **Original campaign bindings:** C02-C07 and C09-C39 lack executable original campaign workflows. Shared events/choices/receipts provide a foundation, but not each real objective or branch-specific proof. C01's final five stages require timing-standard recovery, three-node calibration/consumption, clinic escort, evidence choice and atomic fee/clue. Its cutoff is explicit in [NativeC01ReservationAuditBoard.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/NativeC01ReservationAuditBoard.swift#L61).
2. **Specialised operations:** C05 requires the persistent orbital disaster and genuine reinforcement/evacuation operation; C06 needs resource-control AI, finite reserves, supply movements, permanent commission/decal and both measured settlements; C07 needs actual 900-unit reservoir conservation, baffles, heat, receiver meters and both outcomes. Existing mining/collision/work-job/repair systems are partial foundations, not implementations of these incidents. The accepted Still Current contract already restricts community-buffer transfers to its 300+600 allocation; that resolves the portable omission, but does not implement the physical workflow. Finite-failure recovery findings remain relevant.
3. **G11/G15/W06:** G11 currently has the physical programmer definition/custody boundary but no complete isolation parent/provider/return settlement in this baseline. G15 and W06 lack their own registered family bindings. G07 combat and C08 convoy primitives cannot grant these sources' independent clues.
4. **All-clue progression:** the base catalogue lists 64 sources, but the production trust table authorises only 23 ([ScriptBaseClueCatalog.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/ScriptBaseClueCatalog.swift#L116)). Preserve authenticated terminal evidence; adding a name, relaxed pin or generic completion cannot fill the remaining 41 clues. Even source-wired families need honest post-failure stock so a first success remains achievable.
5. **Finale and Medusa policy conflict:** no native decoded-trail, four ordered flight objectives, exclusive quest encounter, subsequent AI reconstruction or paid quest-fabrication flow was found. [ShipCatalogueMetadata.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/ShipCatalogueMetadata.swift#L249) still requires SH171 to be `xyzzyOnly`, undiscoverable and absent from normal encounters. The runtime purchase-policy enum has no `plughQuestFabrication`. These conflict directly with the intended normal-career finale. Full Medusa art/stats in the new data do not resolve the access policy. The ordinary ship-trade quote checks cash, docking and physical fit but does not consume an AI reconstruction/fabrication entitlement; metadata alone is not that transaction gate.
6. **Gallery and catalogue objectives:** gallery records/rendering are text/progress/trial based, without the mission-art manifest fields required for the 798-asset reveal rules. The comparison renderer uses the same deterministic orientation for both ships ([ShowroomDisplay.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/ShowroomDisplay.swift#L307)); it does not provide the requested arbitrary-plane manual model rotation. New171 data/showroom presence does not certify all player hulls, physical scale, crew/cabins or collection/fabrication access. The clue-progress query API exists; a complete player-facing 64-source journal/missing-source navigation view was not mapped in this baseline.
7. **Stale player-facing availability text:** C01/C08 manifests and older detail strings still describe earlier cutoffs despite later native paths. C08's accreditation code genuinely constructs its terminal receipt and clue ([NativeWayfarerInductionAccreditationBoard.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/NativeWayfarerInductionAccreditationBoard.swift#L54)); the manifest's “only opening” text must not be used to erase that implementation. Conversely, milestone text cannot establish unsupported later work. Reconcile descriptions with the actual final qualified source.

## Correction to the prior coherence review

F02 is also resolved by the existing accepted Still Current contract: its community route permits only the 300-unit delivery and 600-unit retained buffer, excluding optional discharge; material recovery separately accounts for storage/discharge. This restriction is now in the portable rules. No new budget was authored, and the native C07 workflow remains missing.

F04 was a **portable-oracle omission**, not proof that the native game lacked a number. C08 already has a **1,800-second armed-flight allowance** ([NativeWayfarerInduction.swift](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/NativeWayfarerInduction.swift#L519)). Its first original and the later clinic source use that explicit allowance. W01's closed Cedamar-Celalen profile has **2,700 seconds** ([manifest.toml](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/Resources/ScriptPacks/l337-cold-chain/manifest.toml#L28)); W03's reverse seed-transfer profile independently has **2,700 seconds** ([manifest.toml](https://github.com/stephenlclarke/elite/blob/6552b68f7a146ceb79b4376d33cc8afd3f987399/Sources/EliteCore/Resources/ScriptPacks/l337-seed-transfer/manifest.toml#L29)). These existing values have now been recorded in the portable definitions and reading views. Pickup/expiry/reception and finite replacement rules still require the exact native profile; they are not invented defaults for other routes. F03 similarly describes a generic-design lifecycle discrepancy: C01's native pickup/capacity code already implements real 8 kg custody through the audit.

## Acceptance standard

For each objective, require a reachable offer/input action, a native producer of the real physical/economic/consent evidence, exact mission/actor/item/location binding, saved partial/failure/retry state, an authorised terminal and once-only settlement/clue, and truthful journal/gallery presentation. Exercise actual normal controls and each meaningful branch, loss, capacity refusal, cancellation and save/load boundary before marking it playable. Preserve finite resources and actual casualties. Generic conditions, an installed pack, a model, a passing isolated unit or the ability to set a milestone cannot replace that chain.
