# fix(script): make output allocation success explicit

`write_bytes` now keeps its current buffer and capacity in locals. It grows the buffer only when required, then publishes the pointer/capacity, copies bytes and updates the count entirely inside the positive `if (next)` branch. The sole failure branch retains the exact `luaL_error(L, "Output allocation failed.")` call. A failed `realloc` leaves the original allocation in the context for the existing protected-call cleanup. Existing-capacity writes take the same positive path without allocating; publishing the same pointer/capacity does not change ownership or serialized bytes.

The initial output-budget check and the minimum, growth and clamp expressions are unchanged. The current non-returning declaration and all vendor/public/evaluator bytes remain unchanged. None of the six corrected return sites is touched. This makes the nonnull copy visible without adding a dead return or relying on a suppression. It is a source correction for the reported analyzer path, not evidence of a demonstrated native null-copy.

Every supported serialized value emits its tag before a payload. A string also emits its length before a possible zero-length payload; table, scalar and nil values likewise start with a tag. Therefore the existing-capacity path already owns storage for reachable zero-length payloads. This change adds no public zero-length API contract or alternate allocation-error behavior.
