# Preserve actual NPC resources and finite ordinary death cargo

The targeting panel previously inferred facts from hull type and hostility instead of reading each physical ship's current resources, manifest and recorded legal state. Ordinary craft could disappear on camera culling or docking and return with fresh state. Death cargo needed finite, exactly-once custody, including refused admissions and failed saves.

Use actual native shields, energy, heat, fuel, missiles, ECM, manifests, routes and provenance. Keep legacy mission craft energy-only so the original combat is preserved. Retain ordinary NPC identity and physical state across save/load, docking, culling and re-entry; coasting and recharge use actual elapsed simulation time. Admit finite cargo from the recorded manifest once, and preserve deferred deaths until there is ledger capacity. A failed write, docking or escape attempt must not consume resources or erase unsettled cargo.

Acceptance includes actual emitter heat limits, shield absorption, unknown legacy facts, tier-gated compact targeting pages, real native cargo units, finite death/cargo capacity, exact retry, offscreen movement/cooldown, no refreshed hulls or ammunition, correct player/actor rebinding, and unchanged pre-existing save bytes on failure. Required integrated validation is `make ci`, including coverage, both sanitizers and leaks, with renderer-produced media. This checkpoint does not introduce actual NPC hyperspace actions or claim their fuel consumption. See the [implementation and validation handoff](PR-npc-resources-persistence.md).
