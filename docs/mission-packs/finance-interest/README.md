# Original capped simple-interest demonstration

This executable original pack extends the existing native Finance provider. It is not an adaptation of GSE, Iron Raven, Bank of the Black Monks or a complete financial campaign. Install its folder with the normal mission-pack workflow or start its isolated Gallery trial. Visit this system's actual original main orbital doorway, accept the demonstration through Mission Contacts and select Finance in Station Contracts. Borrow/Decline and each Repay require explicit native review and Confirm; Back and reads transfer nothing.

The loan issues 200.0 CR once. It declares 1000 basis points (10%) per completed 86400-second mission-calendar period, rounding each period up to one native monetary unit (0.1 CR). Lifetime assessed interest is capped at 100.0 CR, so total possible repayment is at most 300.0 CR. The rate applies to outstanding principal at each period end, not unpaid interest. A payment first settles all elapsed completed periods, pays interest first, then reduces principal. A mid-period partial payment lowers the principal used at the next period end; it does not restart or postpone that boundary. There is no per-second proration or compounding.

The period origin is the accepted Borrow receipt's real calendar timestamp, not offer creation, mission acceptance or wall-clock time. Native launch, jump and service calendar changes can cross boundaries. Reading, saving and loading do not invent offline elapsed time. Before Borrow, after Decline and after full payoff, no interest accrues. Lifetime interest already assessed never resets after partial payment. For example, one full period on 200.0 CR adds 20.0 CR; paying 70.0 CR then clears that interest and 50.0 CR principal, leaving 150.0 CR. The next period adds 15.0 CR. All figures are original generic product choices, not historical source rules.

Native quotes and Lua `w.finance.workshop` expose current projected principal, accrued interest, assessed lifetime interest, completed periods and declared terms. Projection is read-only. Crossing a period invalidates a captured repayment review; refresh before Confirm. The confirmed receipt freezes exact assessment, principal/interest allocation, cash, calendar and native arrival facts. The existing durable transaction publishes all effects together or restores the whole candidate and prior files on writer failure. There is no automatic cash collection, deadline, default policy, escrow, collection NPC or alternate reward.

Speaking to Mission Contacts after borrowing ends this demonstration but preserves the independent liability and its rate/cap. Missing or terminal parent content cannot erase accepted debt; repayment remains at the original declared station. New offer authorization still requires the exact active parent. Meaningful focused tests are authored for arithmetic, boundaries, current-format persistence, native confirmation/refusal and actual native jump-calendar accrual; compiler/runtime/native/full-quality acceptance remains pending central validation. The interest-free [fixed-principal product](../finance-obligation/README.md) remains available.
