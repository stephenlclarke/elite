# Game-over restart bypasses the genuine starting berth

## Motivation

The first-launch/recovery repair creates an authentic born-berthed Rowan at Avenor, but Game.key still handled game-over Return/Space by constructing a raw Game and preparing equipment only. That new commander displayed DOCKED without a native original-main receipt. ARLEN and other guarded main-station providers would therefore refuse the restarted commander just as they refused the original fresh-start bug.

The actor already restores loaded pack libraries and pending publication acknowledgments around this reset. Those properties are not lost. The missing join is the existing trusted born-berth producer. A later restart must also preserve the bound destination and its existing atomic publication/rollback behavior.

## Bounded repair

Replace only the raw game-over reset with a guarded non-trial restart operation in NativeStationRuntime. It constructs a whole fresh commander through the unchanged file-private bornBerthedCommander producer, preserving the declared executive presentation mode. The public native Game input reaches STATUS only after that producer validates. No raw dock flags, simulated flight, doorway crossing, reward or migrated authority supplies the new receipt.

Keep the actor wrapper, pack restoration, controls rollback, scriptSaveURL, first-publication exclusion and writer barrier unchanged. The born-berth's persistent state now makes an already bound restart publish immediately. A blocked writer or competing first file must leave gameOver, the old commander/owner, pending destination and acknowledgment intact; retry succeeds at that same destination. Publication consumes an unpublished destination and emits its acknowledgment once. Previously published but unacknowledged success remains acknowledged once.
