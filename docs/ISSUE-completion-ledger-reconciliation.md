# Reconcile source repairs without transferring old acceptance

## Motivation

The whole-app review has reviewed source repairs, historical full gates, failed current focused batches and separate publication blockers. Their meanings must remain distinct. A historical passing gate cannot accept later source, and a failed sanitizer, process closure or review service response cannot be silently converted into success.

## Acceptance

Preserve the original review and all retained failure evidence. Carry forward G3's bounded source reconciliation, qualify current Root execution precisely, and explicitly keep the genuine native RRS/P30 prerequisite open. Stage maintained documentation separately from the coordinator's active renderer/quality checkout, without changing game source or hand-editing generated media. Include the maintained research and design handoffs with historical status qualifications, without treating their inventory as installed missions.

The final coordinator handoff must attach actual current CI/media, source hashes, clean completed review, checks, Sonar and publication records before any completion claim. See [the implementation handoff](PR-completion-ledger-reconciliation.md).

The cabin storefront introduces context-specific Return/S/R controls that must be documented in README and the control guide with their actual save and fitting rules. Source integration, a painted control and authored tests must remain distinct from accepted native execution. Record the conditional equipment-help and comparison repairs with their actual focused validation, while keeping remaining patrol-flight and final quality gates open.

The control guide must distinguish ordinary docked commander loads from versioned mission flight/world restoration and retained NPC/mission custody, distinguish legacy dialogs from script choices and repeatable answers, and include delivered Gallery trial/campaign-review/retry/restart/return controls. Retain explicit development-versus-published-release qualifications.

New requests and superseding decisions also need a persistent append-only record so that parallel handoffs cannot silently lose them.

Later EMP, energy, alien stack, missile and drive requests must retain their stable FR IDs and explicit supersessions through FR-028. Integrating reviewed source or correcting test fixtures does not establish runtime acceptance; retain the actual 247 timeout and all unfinished outcomes.
