# Work-frame orientation transfers amplify camera roundoff

Run 542 progressed through the actual first release, partial second cycle, save and reload. It then reported four failures in the original observer-rebase position invariant at `NativeMultiBatchRuntimeTests.swift:150`. The errors were `2.1496252442359806e-7`, `2.271731557618081e-7`, `2.3300734721289295e-7` and `2.03143697751506e-7`. Its original 600-second run later timed out with no method terminal. G1 retained the run's existing temporary save, including all 25 files and generations, with matching before/copied/after hashes. Attribution is the unique temporal/source-fixture contract, not an invented file-open trace. The pre-observer generation `0CAF5DCF-E43F-40B5-80B4-222A6F4D2720` is at physical time 19.299999999999677. Replaying only the existing source's coordinate arithmetic on those retained values reproduces all four original assertion errors exactly, for bodies 0, 1, 2 and 11. This is read-only data analysis, not another game run or a human commander fixture.

The old camera's maximum Gram residual is `5.329070518200751e-15`, but the canonical parent model's is `9.651612842276336e-12`. Observer setup uses that parent basis with axes permuted to `(x, -z, y)`. Because `shipPoint` uses its transpose and `systemPoint` applies the represented basis, the position error is `(P P^T - I)(X - p)` plus ordinary arithmetic rounding. The measured basis residual reproduces the actual distant-body displacement. This is not an unavoidable position-ULP floor and does not justify changing the original `1e-8` assertion.

The amplification comes from work orientation transfers. With represented old/new camera bases `C0`, `C1`, old world model `W` and world spin `R`, the camera change stores `C1^T W`; canonical spin transforms this back to world, rotates it and stores it with another transpose. The next reported world basis is `G R(G W)`, where `G = C1 C1^T`, instead of `R W`. Repeating that represented-camera Gram factor amplifies small camera nonorthogonality into the parent basis.

Use the actual frame inverse at those two orientation re-expression boundaries. Preserve both represented bases without normalization. Do not globally change `ShipPose.shipVector`: certified sweep bounds explicitly enclose its existing transpose-dot arithmetic. The saved history and original fixtures, assertions, tolerances, collision certificates and control behavior must remain intact.
