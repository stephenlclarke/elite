# Agent Rules

If `~/.agents/AGENTS.md` exists, read it and follow it.

Use Swift 6 actor isolation. GameRuntime owns simulation state; AppKit stays on the main actor. Run `make ci` for full normal coverage, static/tooling checks and zero-leak gates. The user removed ASAN and TSAN from required CI on 28 October 2026; sanitizer commands are manual opt-in only and must not be required through local proof bridges. Publish SonarQube analysis only from a committed main branch with the exact commit SHA as projectVersion. README media must be generated by the game renderer with `make readme-media`.

## Completion ledger

Before choosing work, consult `docs/COMPLETION-LEDGER.md` and route the next player-facing batch through Root. Update the ledger when work is assigned, when a frozen delivery completes, and after integration, verification or release, before selecting next work. At assignment record milestone/item ID, owner/session, bounded files/scope, dependencies, status and next handoff. At completion record the frozen commit and focused evidence; at integration record the actual candidate/main commit. Keep functional status, playable build/release location and blockers separate. Keep the owned MBA pipeline supplied with useful bounded tasks; only Root dispatches them, with one MBA task active at a time.

The work-item owner is responsible for implementation, focused unit tests and ensuring those tests PASS. Before integration handoff, the code must be reviewed for bugs, performance and style. Authored UNRUN tests or an unreviewed frozen packet remain in development/validation pending, never ready for integration; the owner coordinates the existing executor lease with G1 and closes findings. Deliver useful batches; run broad integration/system/performance checks after several delivered batches and at formal release checkpoints, rather than repeatedly checking unaffected features or making testing a delivery workstream. Preserve the final required CI, review, checks and release gates. Prepared assets/source and test counts alone never establish playable completion.

## Pull request review

Request `@codex review` once per pushed packet as the existing handoff. The MBA independently reviews the actual project/tap PR for bugs, performance and style, raises actionable GitHub issues, verifies corrected code and relevant hosted unit results, and answers/resolves actual review threads. Latest human direction: ignore generic Codex review-service errors; they are neither code findings nor a clean automated result and do not block proceeding on a clean independent MBA review of the coherent final PR head. Do not retry or investigate those service errors. Actual automated code findings still require disposition and correction/review. Reuse completed reviews and unaffected unit evidence; cover remaining changed code and interactions once. Required GitHub checks and any required independent approval must pass for the final PR head before a protected merge. Do not use administrator bypass or weaken branch protections to merge.
